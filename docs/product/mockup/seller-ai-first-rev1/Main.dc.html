AI-first витрина продавца

Целевой UX по ТЗ «SELLER_AI_FIRST_DESIGN_BRIEF». Путь от товара на прилавке до карточки на витрине: одна кнопка → видео, фото, голос или вручную → пакет черновиков → точки → модерация → витрина. Все фреймы — proposed, не production screens: реализация только после обновления EXECUTION_PLAN и новых Slice Contracts.

Ревизия 1: что изменилось

по SELLER_AI_FIRST_DESIGN_REVISION_1 · дополняет ТЗ, ничего не удаляет
  • AI-S09 — «Pack fields expanded» вместо отдельного шага; «Цена за» открывает Unit sheet; раздельные ошибки цены и единицы; пустая цена без «0».
  • Edit published · All points — комментарий, «Изменить также в других точках», «своя цена», счётчик карточек, без переключателя «Скрыть прежнюю версию».
  • AI-S09 · Points / Submitting / Submit error / Discard confirm / Returned from point, «Изменить только в этой точке» → Edit published · One point.
  • AI-S12A — контакты копируются с предыдущей точки с подписью источника; первая точка — пустые необязательные поля.
  • AI off — витрина со статусами, ручной редактор (disabled «Надиктовать»), правка, Published, «Снято оператором» в карточке и в уведомлениях.
  • Confirm · AI off — сводка, счётчик, блок ответственности; публикация, ошибка, конфликт версий.
  • AI-M06 · Post-check feed — лента «Новые с моего последнего просмотра», снятие с причиной, «Вернуть на витрину».
  • Prototype P4 — ручной путь при выключенном ИИ: от пустой витрины до «Изменить только в этой точке».
  • AI-S04 · Permission primer и Microphone denied — одно действие «видео со звуком», без «отдельного микрофона» (v2, п. 2.4).
  • AI-B07 · Фильтры поиска — сортировка, расстояние, цена; без геолокации, чипы, пустой результат (v2, п. 2.5).
  • Все изменённые и новые фреймы помечены тегом Rev 1

Нельзя реализовать без contract
  • AI ingestion, resumable upload, persisted input, конфликт позднего AI-результата.
  • Media contracts: 5 фото + 1 видео, fallback после жалобы.
  • Moderation / versioning: immutable revisions, независимые исходы, апелляции.
  • Point-owned контакты и verification lifecycle.
  • Multi-point: grouped draft → N Offer, overrides, atomicity.
  • Bulk: смешанный итог против all-or-nothing S12.
  • Lifecycle 2 / 7 / 14 / 30 дней, reminders, hard delete.
  • Отзывы, рейтинг, жалобы, антифрод, audit.
  • AI-B02 route / deep-link; интерактивная карта — только PROPOSED GEO CONTRACT REVISION.

Компоненты: существующие и предлагаемые расширения

Из KAIDA DS

Button (primary / outline / ghost / danger), IconButton, TextField, Checkbox, Radio, Switch, Chip, Badge (success / warning / danger / info / neutral), Card, BottomNav, BottomSheet, Toast, Skeleton, Banner, Icon, иллюстрации «базарная геометрия».

Предлагаемые

CreateCTA, SourcePicker, Recorder (video / voice) + MicMeter, UploadJob, DraftBatchItem, BatchSummary, MediaTile (cover / progress / retry / limit), UnitSelect + PackSize, PointSelector (0 / 1 / many / all), PointOverrides, ContactIcon (phone / WA / TG), CardStatus (lifecycle + revision + task), ActualityPlaque, OutcomeSummary, RatingSummary, ComplaintForm.

Допущения этой итерации

  • Лимит исходных фото в AI-пакете не указан: сетка скроллится, лимит нигде не напечатан.
  • Таймеры повторной отправки OTP не показаны — нет OTP policy.
  • Источник копирования контактов: предыдущая точка, всегда подписан (Rev 1).
  • Сброс актуальности изменённой карточки — после одобрения (рабочая гипотеза п. 12.2), сказано в итоге явно.
  • Примеры товаров, цен и адресов — иллюстративные; фото — нейтральные цветные плейсхолдеры.
  • Расхождения с README дизайн-системы (подписи у иконок связи, Instagram, «Снято …», «свежесть») решены в пользу ТЗ как целевого UX.
