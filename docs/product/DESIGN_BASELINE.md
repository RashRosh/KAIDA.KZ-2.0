# KAIDA — Design baseline (PO 2026-11-05)

## Authority

По прямому поручению PO единственные главные визуальные источники приложения:

1. [Экраны и состояния](https://claude.ai/artifact/X7VZCf7SrZ1pDbn9qZTZDn#artboard-6eb058e9b5c3).
2. [Дизайн-система KAIDA](https://claude.ai/artifact/5xzk5XmbEnpxawj3ZTQovr).

Первый источник задаёт конкретную композицию экранов; второй — токены, typography, компоненты, assets и motion. Старые макеты, дизайнерские brief/revision, Wonder и внешние UX/UI guides больше не имеют визуального приоритета. Их продуктовые решения сохраняются, если не конфликтуют с новым дизайном. Исторический экспорт и существующий CSS описывают старую реализацию, а не новый стандарт.

Это решение о приоритете источников, а не заявление о завершённой миграции. Оно не меняет API, auth/privacy, Offer lifecycle, ranking, актуальность, подтверждение SellerChangeSet, продуктовые thresholds или доступность функций. Конфликт с закрытым пользовательским поведением требует STOP и явной ревизии контракта. Между самими двумя источниками не вводить молча приоритет для противоречащих правил: записать конкретный конфликт и получить решение PO.

Не реализовывать весь холст одним diff. Для каждого шага — компактный Slice Contract, реальные risk flags, targeted/full regression, branch CI, manual acceptance PO и diff audit; затем обычный checkpoint workflow. Не выдавать browser review агента за приёмку PO.

Наблюдённые версии iframe: экранный холст `1793830896-9a07`, система `1793830833-b2b7`. Это идентификаторы открытого содержимого, не архив и не immutable snapshot. Перед реализацией сохранить доступный исходный экспорт выбранной поверхности и проверить соответствие живому источнику.

## Наблюдённые правила системы

- Primary `#9900CC`; фон `#FAF3FE`, surface `#FDFBFF`, sunken `#F4E9FB`; ink `#1F1026`, secondary `#5B406A`, muted `#745784`, line `#E9D9F2`, control line `#9073A0` (светлая тема).
- Roboto 400/500/700 для интерфейса; Geologica для заголовков (400), цен и метрик. Поля 16 px, минимум текста 12 px, tabular numerals для чисел.
- Сетка 4 px; поле экрана 16 px, от 600 px — 24 px. Radius 14 для controls/cards, 20 для banners, 28 для sheet/dialog; pill только для предусмотренных системой элементов. Touch 44 px, основная кнопка 52 px.
- Hover 120 ms только для мыши; pointer press scale .97 / 100 ms; меню 120 ms; dialog 200 ms; sheet 320 ms; уход 120–200 ms. Только transform/opacity/цвет, без transition: all. Reduced motion отключает движение. Тост 5 s с паузой на focus/hover.
- Breakpoints системы 360/600/1024/1280. Bottom navigation до 1024; safe-area учитывается. Это не основание применять grid к поисковому списку: конкретная композиция берётся из экранов.
- Логотип — вопросительный знак из геопина. Иконки QingIcon, исключение — messenger icons Tabler; сохранять лицензии. Не брать старые assets по совпадению имени без сравнения с новыми.

Это краткий указатель прочитанного, а не замена исходных таблиц и CSS. Точные значения конкретного компонента брать из артефакта.

## Разрывы и продуктовые ограничения

**PO review 2026-11-05:** отдельное меню сортировки не принято как достаточный первый результат: окружающая выдача визуально осталась прежней. D2 не закрыт. Перед дальнейшим runtime diff пересмотреть этот же slice до цельной поверхности выдачи после исследования источников; это не разрешение на новые функции, замену поведения или одновременный перенос всего приложения.

Матрица холста явно отмечает отсутствующие desktop/KK/320 px кадры и неполноту прототипа. Система содержит более широкие responsive/dark-theme правила, чем нарисованные экраны. Не объявлять эти поверхности проверенными и не вводить тёмную тему отдельной новой функцией в первом slice.

В README системы продукт назван сервисом рынков; в KAIDA центральная сущность остаётся Offer, а рынок — один из вариантов Location. Примеры лимитов, тарифов, давности, типов точки и операторских правил не становятся бизнес-правилами только потому, что нарисованы. Матрица сама помечает часть этих решений как допущения.

[D1 — First Entry](../slices/design-first-entry/SLICE_CONTRACT.md) **отложен PO 2026-11-05 целиком**: `/welcome` ещё требует обдумывания и не входит в первый slice миграции. Сохранить стрелку при вводе; вопросы навигации и демо рассмотреть при отдельном возврате к экрану. Первый runtime slice — [D2, цельная выдача поиска](../slices/design-search-sort/SLICE_CONTRACT.md), scope пересмотрен после замечания PO: начатый Search B03–B06; закрыт 2026-11-05: приёмка PO, PR #207, checkpoint `v0.0.87-design-search`. Полная инвентаризация и замена старых ссылок/визуальных документов ещё не завершена; не удалять продуктовые требования вместе с дизайнерским текстом.
