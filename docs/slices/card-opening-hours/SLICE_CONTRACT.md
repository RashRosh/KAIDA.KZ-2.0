# Slice Contract — Card opening-hours readability (блок UX/search, пункт 2)

**Статус: APPROVED rev 3 (PO, финальное утверждение контракта и визуалов, версия 4 макета, 2026-10-08).** Поправки PO, внесённые напрямую: чип «сегодня» убран (группа с сегодняшним днём — жирным), дни сокращены (ПН, ВТ…), закрыто → всегда «когда откроется» (кроме расписания без рабочих дней: «Закрыто, рабочих дней нет»), пометка «на след. день» убрана. Реализации нет. Порядок блока — `EXECUTION_PLAN.md`. Рекомендуемый reasoning effort реализации: **medium** (публичный UI покупателя, без данных и миграций; вычисление состояния не меняется). Визуалы — `visuals/index.html` (статический прототип на настоящих стилях и шрифтах приложения; открыть: `node docs/slices/card-opening-hours/visuals/serve.mjs 3300` из корня репозитория, затем `/docs/slices/card-opening-hours/visuals/index.html`).

**Решения PO (rev 2):** на карточках выдачи — только компактная строка статуса, без кнопки и раскрытия; полное расписание — только на странице предложения, развёрнуто, соседние одинаковые дни сгруппированы; строка статуса на всю ширину, значок + слово; день закрытия в ночном статусе — реальный; расчёт и часовой пояс не меняются, фиксированного смещения UTC нет; ограничение tz-базы устройства фиксируется отдельно.

## 1. Пользовательская задача
Покупатель с первого взгляда на карточку понимает, **открыта ли точка сейчас и когда она ближайший раз откроется или закроется**; на странице предложения видит весь режим работы. Режим работы точки **не смешивается** с актуальностью Offer (плашка на фото) и свежестью товара.

## 2. Что есть сейчас (факты из кода)
- `OpeningHoursLine` на карточке выдачи и на странице Offer: значок состояния (круг / часы / крест) + **всегда видимая сгруппированная строка** «9.00–18.00 | ПТ 13.00–18.00 | ~~СБ ВС~~». Слов о состоянии нет: «Открыто до 18:00» живёт только в `title` и `aria-label` значка (решение PO 2026-09-26 «значок без слова»). На длинном KK и при нескольких отличающихся днях строка занимает 2–3 строки.
- Модель — недельное расписание точки: день `closed` / `24h` / 1–3 интервала; интервал с концом не позже начала идёт через полночь; перерыв = два интервала; зона `Asia/Almaty`; режим обязателен при сохранении точки; даты-исключения (праздники) **вне модели**. «Исключения» на экране = дни, отличающиеся от соседних.
- Состояние считается на устройстве раз в минуту (`openingState`): открыто / закрывается (≤60 мин, включительно) / закрыто + ближайшее открытие; границы `[открытие, закрытие)`; переход через полночь, воскресенье→понедельник, слияние 24h с соседним интервалом, перерывы покрыты unit-тестами. **Расчёт не меняется.**

## 3. Предлагаемое поведение (нормативно)
### 3.1 Карточка выдачи: только строка статуса
Одна короткая строка на всю ширину карточки между блоком «фото + текст» и строкой действий (маршрут/контакты): значок состояния (формы сохраняются: круг / часы / крест) + слова. Кнопки, раскрытия и сгруппированной строки на карточке **нет**; строка не интерактивна. Тексты — существующие ключи `hours.*`, одна новая форма:
| Состояние | RU | KK |
|---|---|---|
| открыто, закрытие сегодня | Открыто до 18:00 | 18:00 дейін ашық |
| открыто, закрытие в другой день | Открыто до 3:00 ПН | ДС 3:00 дейін ашық |
| закрывается ≤60 мин | Закрывается в 18:00 | 18:00 жабылады |
| закрыто, откроется сегодня (в т. ч. после перерыва) | Закрыто, откроется в 14:00 | Жабық, 14:00 ашылады |
| закрыто, откроется в другой день | Закрыто, откроется в 9:00 ВТ | Жабық, ВТ 9:00 ашылады |
| круглосуточно, все 7 дней | Открыто круглосуточно | Тәулік бойы ашық |
| никогда не открыта (все дни выходные; следующего открытия не существует) | Закрыто, рабочих дней нет | Жабық, жұмыс күндері жоқ |
| нет данных (защитный случай; схема его не допускает) | Режим работы не указан | Жұмыс уақыты көрсетілмеген |
**Правило PO: закрыто — всегда говорим, когда откроется** («Закрыто, откроется в 9:00 ПН»; в тот же день — без дня). Единственное исключение — расписание без рабочих дней: открытия нет, поэтому статус говорит об этом словами. День недели в статусе — существующие сокращения; между временем и днём — неразрывный пробел. Перерыв отдельным словом не называется («Закрыто, откроется в 14:00»). До монтирования строка не рисуется, место под неё занято (без скачка).

### 3.2 Исправление ночного статуса (явная ревизия текста, не расчёта)
Если день закрытия (`closesAt.weekday`) отличается от текущего локального дня точки, статус называет **этот день**: воскресенье 22:00, закрытие в понедельник в 3:00 → «Открыто до 3:00 ПН»; понедельник 01:30 (закрытие сегодня) → «Закрывается в 3:00» без дня. Текущий день определяется по **времени точки** (`Asia/Almaty`), а не по зоне телефона. `openingState` не меняется (используется уже возвращаемый `closesAt`; текущий день берётся из существующего `localWeekMinute`). **Граница недели:** тесты обязательны для вс→пн, сб→вс, 23:59→00:00 в воскресенье и понедельник, слияния круглосуточных суббота+воскресенье с интервалом понедельника, закрытие ровно в 00:00 следующего дня.

### 3.3 Страница предложения: полное расписание, развёрнуто
В блоке точки (после названия и адреса) — строка статуса (как в §3.1) и под ней **полное расписание, всегда видимое** (кнопки сворачивания нет). Строки: **соседние дни с одинаковым расписанием объединяются**:
- объединяются подряд идущие дни пн→вс (без перехода вс→пн) с идентичным расписанием: одинаковые интервалы, одинаковые перерывы, одинаковые ночные интервалы, одинаковые выходные, одинаковое «круглосуточно»; разные дни остаются отдельными строками;
- подпись — **сокращённые** названия дней (существующие ключи `hours.day.*`): один день — «СБ»; несколько — «ПН–ПТ» / «ДС–ЖМ»; если все 7 дней одинаковы — одна строка «ПН–ВС»;
- **сегодня** (по времени точки): строка (группа) с текущим днём выделена **жирным шрифтом**, без метки и чипа; `aria-current="date"` и скрытый для глаз текст «сегодня» / «бүгін» для скринридера; выделение — вес шрифта, а не цвет;
- время `9:00–18:00` (двоеточие, как в статусе; прежний формат «9.00» остаётся только в `hoursLine`, который с экрана убирается); перерывы — интервалы через запятую, интервал не разрывается; закрытый день — «выходной» / «демалыс»; круглосуточно — «Круглосуточно» / «Тәулік бойы»; ночной интервал — просто «18:00–2:00», без пояснения про следующий день (решение PO);
- при крупном шрифте подпись и время могут встать друг под другом; ничего не обрезается и не уходит за край.
Данные берутся без изменений из `offer.location.openingHours`; каждый интервал сохранённого расписания виден ровно один раз (в одной группе).

### 3.4 Время, зона, границы
Расчёт и границы **не меняются** и не вводится фиксированное смещение UTC: открыто в момент открытия, закрыто в момент закрытия (`[открытие, закрытие)`); «закрывается» — за 60 минут и меньше, включительно; полночь, вс→пн, 24h-слияние, перерывы — как в существующих тестах. Время — местное время точки по tz-базе устройства (`Intl`, `Asia/Almaty`), не зона телефона. Состояние пересчитывается каждую минуту **и при возврате на вкладку/экран** (`visibilitychange`/`pageshow`). Расчёта на сервере нет.

### 3.5 Доступность
Состояние = форма значка + слово + цвет; контраст текста ≥4,5:1 на карточке (проверено: 5,3 / 5,9 / 7,7). Значок `aria-hidden`; статус — обычный текст (скринридер читает его); `aria-live` не используется (минутные обновления не озвучиваются). Расписание — список «Режим работы»; группа с текущим днём `aria-current`, выделена жирным; «выходной» — слово. Размеры относительные, перенос слов разрешён, горизонтального скролла нет. Шрифты — реальные шрифты приложения (Roboto, Geologica).

### 3.6 Что не меняется
Вычисление состояния и схема данных расписания, редактор продавца, валидация, API и публичный DTO (`openingHours`), Search/ранжирование/сортировки/фильтры (часы не влияют), плашка актуальности Offer на фото и её тексты, контакты и маршрут, цена/упаковка, остальная композиция карточки и страницы.

## 4. Вне scope
Цена и упаковка (пункт 3), сортировки и поиск, пустые состояния, опечатки, уведомления, общий редизайн карточки, фильтр «открыто сейчас», праздничные даты и разовые исключения (нет в модели), перевод/транслит, изменение редактора часов, часовой пояс покупателя («по времени точки» не поясняется), «завтра» вместо дня недели, новые иконки, кнопка раскрытия на карточке.

## 5. Закрытые contracts
**Ревизия (явно):** `point-contacts-hours` — «Buyer display of hours»: решение 2026-09-26 «значок без слова» заменяется «значок + слово»; сгруппированная строка с карточки и страницы заменяется статусом (карточка) и сгруппированным расписанием (страница предложения); доступное имя состояния становится видимым текстом; `buyer-screens-mockup` — композиция B01/B02: строка статуса на всю ширину карточки, расписание в блоке точки на странице Offer.
**Только чтение / не меняются:** `offer-actuality` (плашка и её смысл), `S10` (контакты/маршрут), S15B/S15C (Search, D0), UX1B/UX1D, S11 (Nearby), редактор точек и данные.

## 6. Известные ограничения (фиксируются отдельно от решений)
- **Часы и tz-база устройства.** Состояние и «сегодня» считаются по часам телефона и его базе часовых поясов. Старая tz-база может иметь для `Asia/Almaty` устаревшее смещение (+6 вместо +5 после перехода Казахстана на единое время в 2024 году) — тогда статус и отметка «сегодня» на таком устройстве сдвинутся на час. Решение PO: расчёт не меняется, фиксированное смещение не вводится; ограничение записывается в `CURRENT_STATE.md` при закрытии slice. Неверные часы устройства дают неверный статус по той же причине.
- Покупатель в другой зоне видит времена по времени точки без пояснения.

## 7. Risk flags
**Фактические:** публичный UI на каждой карточке выдачи и странице Offer; **новые KK-строки** (несколько: нейтральная строка, «рабочих дней нет», скрытое «бүгін»; названия дней — существующие) требуют вычитки (KK-вычитка — отдельное открытое дело); ограничение tz-базы устройства (§6); рост высоты карточек и страницы; расхождение серверной и клиентской разметки (состояние после монтирования); существующий E2E, привязанный к `opening-hours`/значку (`s10-contact-actions`), и unit-тесты `hoursLine`. **Не затрагиваются:** БД, миграции, API/DTO, Search, ранжирование, auth, внешние сервисы, AI, R2; строка на карточке не интерактивна, поэтому конфликта касаний с растянутой ссылкой карточки нет.

## 8. Acceptance criteria
1. **Статус виден словами на карточке:** для каждого состояния §3.1 видимая строка совпадает с таблицей RU и KK (табличный unit-тест на фиксированных моментах); на карточке нет кнопки, раскрытия и сгруппированной строки.
2. **Расчёт не изменён:** существующие тесты `opening-hours` (состояние, границы, полночь, вс→пн, перерыв, 24h) проходят без правок; смещение UTC не зашито.
3. **Ночной статус называет реальный день:** вс 22:00 / закрытие пн 3:00 → «до 3:00 ПН»; пн 01:30 → без дня; граница недели (вс→пн, сб→вс, 23:59→00:00, закрытие ровно в 00:00 следующего дня, слияние 24h с интервалом) закреплена тестами; текущий день берётся по зоне точки (тесты с разными `TZ`).
4. **Расписание на странице Offer:** всегда видимо; соседние одинаковые дни сгруппированы (одинаковые интервалы, перерывы, ночные интервалы, выходные, 24h); различающиеся дни отдельно; все 7 одинаковых → одна строка; каждый интервал сохранённого расписания виден ровно один раз; вс и пн не объединяются.
5. **Сегодня внутри группы:** группа с текущим днём выделена жирным шрифтом (без чипа и метки), `aria-current`, скрытый текст «сегодня» для скринридера; без опоры на цвет.
6. **Особые случаи:** все 24h → «Открыто круглосуточно» и одна строка расписания; все выходные → «Закрыто, рабочих дней нет» и одна строка «ПН–ВС выходной»; нет данных → нейтральная строка.
7. **Не только цвет, доступность:** форма значка + слово; контраст ≥4,5:1; значок скрыт от скринридера, статус читается как текст; расписание — список с названием; пересчёт раз в минуту и при возврате на вкладку; нет расхождения серверной/клиентской разметки и скачка.
8. **Узкая ширина, длинный KK, крупный шрифт, реальные шрифты:** при 320 px, KK и увеличении текста до ×2 ничего не обрезается, не наезжает и не создаёт горизонтальный скролл (проверка переполнения в E2E на мобильном профиле, шрифты Roboto/Geologica; реальный телефон — у PO).
9. **Отдельно от актуальности:** плашка актуальности и её тексты не меняются и не используют слова/цвета режима работы; часы по-прежнему не влияют на ранжирование, видимость, фильтры (существующие тесты S9/S11/actuality без правок).
10. **Строки RU/KK:** все новые ключи есть в обоих языках, проверка равенства наборов ключей; KK помечены на вычитку.
11. **Регрессия:** маршрут и контакты на карточке и странице Offer работают; `/api/search` и `/api/offers` не меняются (snapshot); `pnpm verify` зелёный.

## 9. Verification (агентская)
Unit — форматирование статуса (в т. ч. TZ и граница недели), группировка расписания (одинаковые интервалы/перерывы/ночные/выходные/24h, вс≠пн, все 7 одинаковы, сегодня в группе), ключи i18n; E2E (mobile + desktop, ru + kk) — статус по подменённому времени, расписание на странице Offer, нет кнопок на карточке, переполнение при 320 px и крупном шрифте; `pnpm verify`. Агент подготовит тестовую точку(и) с расписаниями «открыто сейчас», «закрывается», «закрыто, откроется завтра», «перерыв», «ночная смена», «круглосуточно» под время проверки, не трогая существующие записи; ID сохраняются для очистки. **Не проверено** (будет в отчёте): реальные телефоны с разной tz-базой, KK-вычитка.

## 10. Manual acceptance (PO, телефон, покупатель)
1. Открыть выдачу по товару, у которого есть карточки тестовых точек. **Не открывая ничего**, по строке под адресом сказать про каждую точку: открыта ли сейчас и когда закроется/откроется (на карточках нет кнопок расписания).
2. Открыть страницу предложения точки с будничным расписанием: видно сгруппированное расписание («ПН–ЧТ», «ПТ», «СБ–ВС»), группа с сегодняшним днём выделена жирным. Открыть страницы точек с перерывом и с ночной сменой.
3. Переключить интерфейс на казахский и повторить: строки не обрезаны и не выходят за край; затем включить крупный системный шрифт (и узкий телефон, если есть) — всё читается.
4. Убедиться, что плашка «N дней» на фото осталась прежней и не связана со строкой режима работы.
PO принимает: ответ «открыто/закрыто, когда» понятен на карточке без действий, расписание на странице понятно и сгруппировано, RU/KK читаются. Технические проверки — агентские.

## 11. Решения PO (приняты)
A сокращённые названия дней (ПН, ВТ, СР… / ДС, СС, СР…), чип «сегодня» убран — сегодняшняя группа выделяется жирным; B расписание на странице Offer развёрнуто (всегда видимо); C день в ночном статусе; D расчёт и tz — без изменений, без фиксированного смещения; E строка статуса на всю ширину; F «завтра» не вводится; G времена по времени точки без пояснения; расписание и кнопка на карточке выдачи **убраны**; группировка соседних одинаковых дней на странице Offer.

## 12. STOP conditions
Нужно менять расчёт состояния, модель/данные расписания, API/DTO, Search/ранжирование, плашку актуальности или редактор часов; нужны новые иконки, миграции или серверное вычисление состояния; нужно зашить смещение UTC; текст/KK не помещаются при ×2 без обрезки; PO не подтвердил финальные визуалы.
