## User task

Впервые открыв KAIDA, покупатель понимает назначение сервиса и отправляет свой запрос в существующий поиск без регистрации.

## Scope

Только `/welcome`, B01.ST01–ST02 нового [design baseline](../../product/DESIGN_BASELINE.md). Новые visual tokens, логотип, typography, layout, поле, кнопка, демонстрационный блок и вход продавца. Подключение к существующему submit/navigation, locale и seller-entry без изменения API/core. Состояния ввода, invalid, busy, reduced motion должны быть описаны по источнику до реализации; матрица признаёт отсутствие B01.ST03 в контексте.

## Explicit out of scope

Search Home B02 и выдача B03, Nearby, offer details, auth redesign, кабинет продавца/оператора, тёмная тема, новые функции, новые endpoints/миграции, новая аналитика, реальные внешние вызовы. Нет глобальной замены shared CSS, затрагивающей остальные экраны. Старый экспорт нельзя удалять, пока от него зависит runtime.

## Закрытые contracts и STOP

Затронуты `first-entry-mobile`, `first-entry-correction`, `inline-language`, `seller-entry-contextual-auth`, Search intent/D0. Core semantics сохраняются.

1. **Навигация:** `first-entry-correction` §3.3 сохраняет нижнюю навигацию из `first-entry-mobile`. B01 её не показывает. Удаление убирает прямые переходы с onboarding на Search/Nearby/More. Требуется разрешить узкую ревизию только `/welcome` либо явно принять отклонение от B01.
2. **Submit:** `first-entry-mobile` §2 Search и AC4 запрещают постоянную кнопку: стрелка появляется только с текстом. B01 показывает постоянную «Искать». **Решение PO 2026-11-05: сохранить стрелку при вводе.** Постоянная кнопка из B01 не переносится; это разрешённое отклонение от нового кадра. Пустой запрос не отправляется.
3. **Demo:** старый contract требует две карточки, особую ≈3.5 s сцену, остановку/скрытие при focus и storage marker. B01 показывает одну карточку томатов с явным «Демо» и disclaimer; motion системы исключает движение списков/цен. В DOM выбранного B01 нет активных CSS-анимаций; кадр подписан «демонстрация завершена». Отдельная начальная сцена ещё не найдена. PO отложил весь экран; вариант демо остаётся открытым до возврата к нему. Новый тайминг не придумывать.

Следствия: изменения ограничены buyer First Entry и его E2E/locale presentation; общие buyer routes, API, ranking, auth, D0 и marker semantics не пересматриваются. Вопрос навигации отложен вместе с экраном решением PO 2026-11-05. По кнопке PO выбрал сохранение стрелки. Наличие этого draft не означает approval.

## Предлагаемые acceptance criteria

1. Mobile RU `/welcome` соответствует B01 по композиции/шрифтам/цветам/spacing после утверждения оговорённых ревизий; проверка на 360 и 390 px.
2. Поиск валидного запроса ведёт в существующий `/?q=…`, Enter работает, пустой запрос не отправляется.
3. First-entry handoff сохраняет текущую intent/D0 semantics; нет дополнительного события ради demo.
4. Intro marker ставится при показе; следующий обычный `/` ведёт на Search; deep links не перехватываются.
5. Полные Русский/Қазақша применяются inline, без сброса запроса/маршрута; оба каталога имеют ключи; нет overflow от 320 px.
6. Demo явно обозначено как иллюстрация; никаких звонков/маршрутов/геолокации/сетевых Offer-запросов из примера. Точный новый demo lifecycle — только после решения §STOP.
7. «Я продавец» вызывает существующий contextual seller entry, сохраняет обратный переход и введённый запрос.
8. Focus-visible, доступные имена, validation announcements и touch targets сохраняются; reduced motion отключает движение.
9. Соседние buyer/seller/operator поверхности, domain/API/DB и закрытые гарантии не меняются.
