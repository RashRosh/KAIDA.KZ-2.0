# Slice Contract — Card price and packaging clarity (блок UX/search, пункт 3)

**Статус: DRAFT rev 3 — ожидает подтверждения визуалов PO.** Rev 3 заменяет rev 1–2 по решениям PO (цена «/ количество», без «за»; ровно 1 единица — без числа). Реализации нет. Порядок блока — `EXECUTION_PLAN.md`. Рекомендуемый reasoning effort реализации: **medium** (публичный UI покупателя; без данных, миграций, изменения DTO и ярлыков продавца/оператора). Визуалы — `visuals/index.html` (статический прототип на настоящих стилях и шрифтах приложения; открыть: `node docs/slices/card-price-packaging/visuals/serve.mjs 3300` из корня репозитория, затем `/docs/slices/card-price-packaging/visuals/index.html`).

## 1. Пользовательская задача
Покупатель с первого взгляда понимает, **какое количество покупается за показанную цену**, без повторов и без неоднозначного «/ упак.» там, где продавец указал количество.

## 2. Что есть сейчас (факты из кода и контрактов)
- Данные продавца: название (свободный текст), цена, единица `kg` / `piece` / `liter` / `package` / `other` (своя единица ≤40 знаков, текст продавца) или «не указана», и **необязательное количество упаковки** `pack` (сумма + `г`/`кг`/`мл`/`л`), разрешено только при `package` и `piece` (`offer-price-unit`, `seller-showcase-editor`).
- Покупатель видит: на карточке — название, **отдельную строку упаковки** («500 г», мельче), затем «2 100 ₸ / упак.»; на странице — то же с крупной ценой. Публичный DTO: `price.unit` — строка-ярлык языка интерфейса (`упак.`, `қапт.`, `кг`, `шт`/`дана`, `л`, свой текст) и `pack` — готовая строка («500 г»); кода единицы в DTO нет.
- Проблемы (на снимках): «1 литр» в названии + «1 л» отдельной строкой + «/ упак.»; сыр «500 г» в названии и отдельной строкой; «/ упак.» не говорит, что внутри упаковки.
- Сортировка «по цене» — по номинальной сумме (Rev 3): единицы и упаковки не нормализуются.

## 3. Правило показа (нормативно, решения PO)
### 3.1 Основа цены — по приоритету
1. **Продавец указал количество упаковки (`pack`)** → «{сумма} ₸ / {количество}»; ярлык единицы/тары **не показывается**. Если количество — **ровно 1 единица измерения** (`1 г`, `1 кг`, `1 мл`, `1 л`), число опускается: «/ л», «/ кг».
2. Количества нет, единица есть → «{сумма} ₸ / {единица}» (ярлык как сейчас; своя единица — как написал продавец).
3. Нет ни единицы, ни количества → только «{сумма} ₸».
Всё через единый знак «/», без слов «за» и «үшін», одинаково в RU и KK. **Никаких пересчётов:** «1000 г» остаётся «/ 1000 г» (не «/ кг»); «500 г» — «/ 500 г»; цена не нормализуется, количество не выводится из названия, данные продавца не переписываются.

### 3.2 Таблица (RU = KK по форме; ярлыки на языке интерфейса)
| Данные продавца | RU | KK |
|---|---|---|
| упаковка, 800 г, 4 000 ₸ | 4 000 ₸ / 800 г | 4 000 ₸ / 800 г |
| упаковка, 250 мл, 1 500 ₸ | 1 500 ₸ / 250 мл | 1 500 ₸ / 250 мл |
| упаковка, 500 г | 2 100 ₸ / 500 г | 2 100 ₸ / 500 г |
| упаковка, **1 л** (мёд) | 4 500 ₸ / л | 4 500 ₸ / л |
| упаковка, **1 кг** | 4 500 ₸ / кг | 4 500 ₸ / кг |
| упаковка, **1000 г** | 900 ₸ / 1000 г | 900 ₸ / 1000 г |
| штука, 200 г | 250 ₸ / 200 г | 250 ₸ / 200 г |
| кг (единица, количества нет) | 4 200 ₸ / кг | 4 200 ₸ / кг |
| литр (единица) | 4 500 ₸ / л | 4 500 ₸ / л |
| упаковка без количества | 800 ₸ / упак. | 800 ₸ / қапт. |
| своя единица (пучок, коробка, любая) | 150 ₸ / пучок | 1 800 ₸ / қорап |
| ни единицы, ни количества | 1 200 ₸ | 1 200 ₸ |
- Условие «ровно 1»: числовое значение количества равно 1 и единица измерения одна из `г`/`кг`/`мл`/`л`. «1,5 л», «10 л», «1000 г» числа не теряют.
- **Своя единица** (и вообще любая единица без количества) показывается как есть после «/» — без склонения и угадывания окончаний: «/ пучок», «/ связка из трёх пучков». Одна запись для любого текста продавца в обоих языках.
- Знак валюты и формат суммы — существующие (`₸`, разряды неразрывным пробелом, как сейчас); «/» отделён от суммы обычным пробелом и связан с единицей/количеством неразрывным пробелом (не остаётся в конце строки; число и единица измерения количества не разрываются). Сумма не переносится; длинная единица переносится по словам.
- Карточка: цена 16/14 px, как сейчас; страница: крупная сумма, «/ …» рядом обычным шрифтом.

### 3.3 Убирается
Отдельная строка с упаковкой над ценой (карточка и страница), пометка «Размер упаковки не указан» (из rev 1), слова «за»/«үшін» (из rev 2) — **не вводятся**. Упаковка без количества просто показывает «/ упак.».

### 3.4 Что продавец ввёл — то и показываем
Название, цена, единица и количество не меняются, не переписываются, не пересчитываются. Если продавец написал «Мёд липовый 1 литр» и количество «1 л», покупатель видит «1 литр» (текст продавца) и «/ л» — повтор остаётся только там, где его создал продавец; сопоставление названия с количеством и скрытие «дубля» не вводятся (решение B). Нет перевода «за кг», нет сравнения единиц, порядок сортировки не меняется.

### 3.5 Названия
Длинное название на карточке — до 2 строк, как сейчас; на странице — целиком. Цена не зависит от длины названия.

### 3.6 Что не меняется
Публичный DTO (`price.unit` строка-ярлык, `pack` строка; клиент выбирает, что показать), **канонические ярлыки единиц** (`упак.`, `қапт.`, `кг`, `шт`/`дана`, `л`) и все экраны продавца и оператора, цены и их формат, коды единиц, правила ввода и допустимости количества (`packAllowedFor`), редактор продавца, сортировки и допуск Search, подсказки, режим работы, плашка актуальности, контакты, маршрут.

## 4. Вне scope
Пересчёт или нормализация цены (за кг/л), приведение «1000 г» к «кг», сравнение или сортировка по цене за единицу, вывод количества из названия, автоправка названий, количество для своих единиц, новые единицы, разрешение количества для кг/л, изменение формата суммы, редактор продавца и экраны оператора, смена ярлыков, пустые состояния, опечатки, общий редизайн карточки.

## 5. Закрытые contracts
**Ревизия (явно):** `offer-price-unit` — уточнение: для покупателя заданное количество упаковки становится основой показа цены («/ 500 г»; ровно 1 единица — «/ л»), а не отдельной справкой; формат строки количества, ярлыки, коды и ввод не меняются; `buyer-screens-mockup` — композиция B01/B02: отдельная строка упаковки убрана, строка цены строится по §3.1.
**Проверить на противоречие (без изменения, если его нет):** `seller-showcase-editor` — подсказка у поля количества («размер не является единицей цены» или подобное), если есть в строках интерфейса; при противоречии — единичная правка текста в рамках этого slice, иначе только чтение.
**Только чтение / не меняются:** `mandatory-offer-price`, S9 / Search sort Rev 3 (тесты меняются только если ожидали «/ упак.» вместе с количеством), S15B, S10, S11, `offer-actuality`, `card-opening-hours`.

## 6. Risk flags
**Фактические:** публичный UI на каждой карточке и странице Offer; при количестве ярлык тары скрыт — покупатель не видит «упаковка»/«штука» (решение PO); **«250 ₸ / 200 г» у штучного товара** не говорит «за штуку»; **«/ 800 г» читается как «цена за 800 г»**, но без слова — смысл держит привычная запись «/», приемлемо по решению PO; **«/ л» и «/ кг» при количестве 1** визуально неотличимы от цены за литр/килограмм — по существу это тот же смысл; «1000 г» не приводится к «кг» — цены «/ 1000 г» и «/ кг» рядом не сравнимы без пересчёта (по решению PO, пересчёта нет); повтор количества из названия продавца остаётся; существующие тесты/E2E, ожидающие «/ упак.» вместе с количеством или строку упаковки; перенос длинной своей единицы и крупный шрифт. Новых KK-слов нет (только числа, единицы измерения и «/»); вычитка KK-ярлыков остаётся открытым делом. **Не затрагиваются:** БД, миграции, форма API/DTO, ярлыки продавца/оператора, Search и ранжирование, auth, внешние сервисы, AI.

## 7. Acceptance criteria
1. **Приоритет основы цены:** количество → «/ количество» без ярлыка; иначе «/ единица»; иначе только цена; табличный unit-тест по §3.2 (RU и KK), включая примеры PO («4 500 ₸ / 800 г», «1 500 ₸ / 250 мл»).
2. **Ровно 1 единица:** `1 л` → «/ л», `1 кг` → «/ кг» (также `1 г`, `1 мл`); `1000 г`, `1,5 л`, `10 л` сохраняют число; никакой конвертации (unit-тест).
3. **Нет отдельной строки упаковки, пометки о размере, слов «за»/«үшін»** на карточке и странице; количество видно ровно один раз.
4. **Своя единица** показывается как написана после «/», в том числе длинная; «/ кг», «/ л» сохраняются; нет ни единицы, ни количества → только цена.
5. **Данные продавца не тронуты:** название, сумма, код единицы, свой текст и количество в БД и во всех чтениях те же; форма DTO (`price.unit: string | null`, `pack?: string`) и значения ярлыков не меняются (snapshot `/api/search`, `/api/offers` без различий).
6. **Без пересчётов и смены сортировки:** сортировка «по цене» даёт тот же порядок (S9/Rev 3 проходят); количество не выводится из названия.
7. **Перенос и ширина:** сумма не рвётся; «/» не остаётся последним символом строки; число и единица измерения количества не разрываются; длинная единица переносится по словам; длинное название — 2 строки на карточке, целиком на странице; при 320 px, KK и увеличении текста до ×2 нет обрезки и горизонтального скролла (E2E на мобильном профиле; реальный телефон — у PO).
8. **Экраны продавца и оператора без изменений:** ярлыки, выбор единицы, создание и правка цены/единицы/количества работают как раньше; RU/KK строки интерфейса не получают новых слов (проверка равенства наборов ключей остаётся зелёной).
9. **Регрессия:** маршрут, контакты, режим работы и плашка актуальности не изменились; `pnpm verify` зелёный.

## 8. Verification (агентская)
Unit — построение строки цены по таблице §3.2 (RU/KK), правило «ровно 1» и приоритет основы; integration — DTO и сортировка по цене без изменений; E2E (mobile + desktop, ru + kk) — карточка и страница для каждого случая, переполнение при 320 px и крупном шрифте; `pnpm verify`. Агент подготовит тестовые карточки (отдельный тестовый продавец) для каждого случая в dev-базе, не трогая существующие записи; ID сохраняются для очистки. **Не проверено** (будет в отчёте): реальные телефоны.

## 9. Manual acceptance (PO, телефон, покупатель)
1. Открыть выдачу по поисковому слову тестовых карточек: творог 800 г, сок 250 мл, мёд 1 л, орехи 1 кг, мука 1000 г, сыр 500 г, курага шт 200 г, баранина кг, сок упаковка без количества, укроп «пучок», яйца «коробка», яйца без единицы.
2. **Не открывая карточки**, по строке цены сказать, что покупается за эту цену; убедиться, что нет отдельной строки упаковки, слов «за» и «Размер не указан».
3. Открыть страницу творога и страницу сока без количества: та же строка, крупная цена.
4. Включить сортировку «по цене»: порядок по числу, без пересчёта на кг.
5. Переключить интерфейс на казахский и повторить; затем крупный системный шрифт (и узкий телефон, если есть): ничего не обрезано, «/» не повисает.
6. В кабинете продавца выбор единицы и количества выглядит как раньше.
PO принимает: за какое количество цена — понятно без раскрытия, повтор не добавлен нами, данные продавца не изменены, RU/KK читаются. Технические проверки — агентские.

## 10. Решения PO
Принято PO: основа цены — количество (иначе единица продавца, иначе только цена); единый знак «/», без «за»/«үшін»; ровно 1 единица — без числа; без конвертации; ярлык тары скрыт при количестве; отдельная строка упаковки и пометка о размере убраны; ярлыки продавца/оператора не меняются.
Остаётся подтвердить (рекомендации — первые):
- **A. «250 ₸ / 200 г» для штучного товара** (слово «шт» скрыто): подтвердить.
- **B. Повтор из названия продавца** («Мёд 1 литр» + «/ л»): оставить как есть (рекомендуется: сопоставление текста — домысливание) либо скрывать при совпадении (эвристика, не вводится).
- **C. Единица «ровно 1»:** применяется к `г`, `кг`, `мл`, `л` (рекомендуется) либо только к `кг` и `л`.
- **D. Ярлыки «упак.»/«қапт.»** без количества остаются (рекомендуется: общий владелец, виден продавцу/оператору); полные слова — отдельный slice при необходимости.
Утвердить также визуалы: карточка, страница, KK, 320 px, крупный шрифт.
