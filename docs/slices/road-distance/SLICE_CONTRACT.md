# S-ROAD-DISTANCE

Реализация для закрытого пилота. База `v0.0.93-route-https-223`, коммит `a9efc797`.

Покупатель с уже полученной геопозицией видит расстояние по автомобильным дорогам до точки продажи в поиске, «Рядом» и на странице предложения. Километры по дороге показаны обычным числом. При неполном расчёте над списком появляется одна подпись «Расстояния указаны по прямой». Страница предложения сохраняет число из списка и уточняет «по прямой», когда применялся запасной вариант. При прямом открытии предложения без текущей геопозиции расстояние отсутствует.

## Поведение

- Для поиска дорожное расстояние меняет порядок только в сортировке по расстоянию. Сохраняются направление, порядок при равенстве и положение предложений без координат. Остальные сортировки, включая релевантность, сохраняют порядок.
- «Рядом» отбирает предложения тем же радиусом по прямой. При полном дорожном расчёте меняется порядок внутри существующих групп актуальности. Недоступность сервиса и предел числа точек не исключают предложения из выдачи.
- KAIDA отправляет с сервера один запрос OSRM Table от покупателя к уникальным торговым точкам итогового списка. Лимит, тайм-аут, недостижимая точка, плохая привязка старта или финиша и некорректный ответ означают возврат к прямым расстояниям для всего списка. Поиск с исправлением опечатки обращается к OSRM после завершения проверки исправленного запроса.
- Публичное поле `distanceMeters` сохраняет прямую дистанцию. При полном дорожном расчёте ответ добавляет `distanceBasis: "road"` для списка и `roadDistanceMeters` для каждой точки с координатами. Отсутствие `distanceBasis` означает прежнее поведение. Публичные ответы не содержат сырых координат.
- При переходе к карточке передаются только вычисленное расстояние и его тип в памяти вкладки. Новая выдача сбрасывает передачу прежнего значения. В действующей кнопке маршрута, геолокации, правиле соответствия товаров, доступности предложений, БД и бизнес-логике Offer изменений нет.
- По уточнению владельца продукта от 22 ноября километры в плитке «Рядом» открывают существующий маршрут в 2ГИС в новой вкладке, когда маршрут доступен. Клик по фото или названию открывает предложение. Это уточнение к плитке B07 относится к обоим типам расстояния.

## Пилот

Локальный OSRM использует автомобильный профиль и выгрузку OpenStreetMap для Казахстана. Сравнение с 2ГИС и проверка 24 пар в Алматы поддержали выбор OSRM для закрытого пилота. На предварительной локальной проверке один запрос к шести точкам занимал 8,4 мс по медиане и 11,3 мс по p95. Потребление памяти работающего OSRM составило 565,6 МиБ.

Включение и ограничения определяются серверной конфигурацией в `.env.example`. Для старта использованы шесть точек и допустимое смещение 50 м, исходя из предварительных замеров количества точек и смещения финишей до 40,6 м. На стенде проверяются оба конца маршрута, конкуренция и пригодность меток подъездов.

На Windows скрипт `ops/road-distance/start-osrm.ps1` собирает граф, печатает версию образа и хеш карты и оставляет контейнер доступным по loopback. Укажите напечатанные `OSRM_BASE_URL` и `OSRM_GRAPH_VERSION` вместе с `ROAD_DISTANCE_ENABLED=1` при запуске KAIDA. Скрипт выключает журнал HTTP-запросов OSRM, поскольку путь запроса содержит координаты.

## Риски и приёмка

Проверяются новые поля API, временный кеш по исходной позиции и точкам, объединение одновременных одинаковых запросов, тайм-аут, приватность координат и отказ отдельного сервиса. Миграция БД не требуется.

1. На работающем OSRM открыть Поиск с сортировкой по расстоянию и «Рядом». Проверить дорожные значения и порядок двух точек, а также одинаковое значение для нескольких предложений одной точки.
2. Открыть предложение из списка, проверить одинаковое расстояние и кнопку «Маршрут». Повторить с другой отправной точкой.
3. Временно остановить OSRM и повторить обе выдачи. Проверить прямые значения, единую подпись, старый порядок и сохранённые предложения. Снова запустить OSRM и проверить возврат дорожных значений.
4. Проверить русскую и казахскую подписи на мобильном. На тестовых данных сверить точки и подъезды в 2ГИС.
5. Записать задержку полного API на нескольких точках и параллельных запросах, память OSRM при работе и пик памяти при сборке графа.

Закрытие проходит после targeted tests, полной регрессии, CI ветки, ручной приёмки владельцем продукта, аудита diff, слияния, CI `main` и аннотированного тега.
