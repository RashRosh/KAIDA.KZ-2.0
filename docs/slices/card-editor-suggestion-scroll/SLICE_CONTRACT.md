# Card editor — mobile visibility of catalog suggestions

**Status:** CLOSED. Checkpoint `v0.0.55-card-editor-suggestion-scroll`; PR #101; `main` `ff8f08e3644af216dc2833b358610e213f7a1829`; merged-main `KAIDA verify` run `37347918337` SUCCESS; manual acceptance PASS (implementation `b70b530`).
**Base:** `main` (checkpoint `v0.0.53-catalog-runtime-loop`). Не зависит от S15B-1 (другие файлы), но реализуется после его закрытия.
**Граница доставки:** mobile + русский (`PROJECT_RULES.md` §18.5).

## 1. User task

На телефоне при вводе «Название товара» экранная клавиатура закрывает значительную часть выпадающего списка подсказок каталога. Когда список подсказок открывается, поле должно само подняться почти к верху рабочей области, чтобы несколько подсказок были видны над клавиатурой.

## 2. Фактическое поведение (evidence)

- `CardEditor` (`src/app/seller/_components/CardEditor.tsx`): список подсказок — `ul[role=listbox]` с `position:absolute`, раскрывается вниз от поля (`top: 78`). Он открыт, когда `titleFocused && !suggestDismissed && suggestions.length > 0` (`suggestOpen`).
- Прокручиваемая область — существующий `main.body` (`overflow-y:auto`, `kaida-app.css`). Автопрокрутки к полю названия нет; в редакторе уже есть `scrollIntoView` только для фото.

## 3. Behavior

1. Пока список подсказок закрыт, форма сама не прокручивается.
2. Переход `suggestOpen`: закрыт → открыт (непустой список) запускает **одну** прокрутку: блок поля «Название товара» (метка + input + список) выравнивается по верху видимой scroll-area с небольшим верхним отступом 8–16 px. Прокрутка внутри существующего контейнера (`scrollIntoView`/эквивалент с `scroll-margin-top`), без расчёта высоты клавиатуры и без привязки к размерам viewport.
3. Список по-прежнему раскрывается вниз от поля.
4. Пока сеанс открыт (ввод следующих символов, смена списка, навигация стрелками) повторной прокрутки нет.
5. После закрытия списка (выбор, Escape, blur, пустой результат) и нового открытия прокрутка срабатывает снова: флаг сбрасывается при `suggestOpen = false`.
6. Автопрокрутка разрешена только если текущий сеанс работы с полем «Название товара» начат **touch-взаимодействием с этим полем** (`pointerType === 'touch'` или эквивалентное локальное определение фактического touch input). Фокус мышью, трекпадом или клавиатурой сам по себе прокрутку не запускает. Не используются `matchMedia('(pointer: coarse)')`, ширины viewport, высота клавиатуры, `visualViewport`. После blur / завершения touch-сеанса состояние сбрасывается; следующий сеанс определяется заново.
7. Выбор подсказки, клавиатурная навигация, Escape, blur, `linkedName`/`productId`, запросы и ранжирование подсказок, `aria-*` — без изменений.

## 4. Scope / out of scope

**In scope:** ref/якорь на блок поля названия; отслеживание перехода closed → open; одна прокрутка за сеанс; минимальный E2E (mobile) и существующие тесты автокомплита.

**Out of scope:** редизайн автокомплита; backend, API `GET /api/catalog/suggestions`, ранжирование (S15B-1), БД, каталог; расчёт высоты клавиатуры / `visualViewport`; перепозиционирование списка вверх; рефакторинг `CardEditor` и CSS рядом; адрес-подсказки точек (`AddressSuggestionInput`); buyer-экраны.

## 5. Affected closed contracts

`seller-showcase-editor` (редактор карточки, смешанный ввод, подсказки): поведение подсказок не меняется, добавляется только прокрутка. `PROJECT_RULES.md` §18.4 (overlay/focus) не затрагивается: новый overlay не вводится, фокус не переносится. Ревизий не требуется.

## 6. Design gaps (`feedback_design_gaps_ask`)

В макете нет кадра «редактор с открытой клавиатурой и подсказками». Решение (прокрутка почти к верху, отступ 8–16 px, один раз за сеанс) задано PO в этом контракте; других визуальных изменений нет.

## 7. Risk flags

DB migration: no · public API: no · auth/security/privacy: no · concurrency/atomicity: no · data loss: no · external service: no. Только клиентская прокрутка в одном компоненте.

## 8. Acceptance criteria

1. Без подсказок форма не прокручивается (в том числе при вводе 1 символа).
2. При первом открытии непустого списка в mobile-viewport блок поля оказывается у верха scroll-area с отступом 8–16 px; список раскрыт вниз.
3. Дальнейший ввод в том же сеансе не вызывает повторной прокрутки.
4. После закрытия списка (Escape / выбор / blur) и нового открытия прокрутка срабатывает снова.
5. Выбор подсказки, стрелки + Enter, Escape, blur, привязка к Product работают как раньше; существующие тесты автокомплита (`seller-showcase-editor`, `catalog-runtime-loop`, `seller-change-set`) зелёные без изменения утверждений.
6. Прокрутка зависит от фактического touch-сеанса: после touch-тапа по полю — срабатывает; при фокусе мышью или клавиатурой (в том числе на том же устройстве после сброса сеанса) — нет.
7. Нет изменений в backend/API/ranking/БД/каталоге; diff ограничен `CardEditor.tsx` (и тестом).

## 9. Verification

Targeted E2E: touch-сеанс (тап по полю в touch-проекте) — `scrollTop` контейнера не меняется без подсказок, меняется один раз при открытии, не меняется при дальнейшем вводе, меняется снова после закрытия и повторного открытия; mouse/клавиатурный фокус (desktop-проект или клик мышью) — не меняется. Положение поля у верха проверяется относительно scroll-контейнера, без привязки к высоте клавиатуры. Затем полная регрессия, branch CI, manual acceptance на телефоне с реальной клавиатурой.

## 10. Manual acceptance (телефон, русский)

1. Открыть «Новая карточка».
2. Тапнуть пальцем «Название товара» (именно touch-тап).
3. Ввести минимум 2 символа, например «ба». Дождаться подсказок.
4. Поле автоматически поднялось почти к верху рабочей области, несколько подсказок видны над клавиатурой.
5. Продолжить ввод «бар…» — экран повторно не прыгает.
6. Закрыть подсказки (Escape/тап вне поля) и открыть снова — автопрокрутка срабатывает снова.
7. Выбрать подсказку — форма ведёт себя как раньше.

## 11. STOP conditions

- Нужно считать высоту клавиатуры / `visualViewport` или привязываться к размерам viewport.
- Прокрутка конфликтует с фокус-ловушкой overlay или поведением `Sheet` (`PROJECT_RULES.md` §18.4).
- Требуется менять CSS/структуру за пределами якоря поля или другие компоненты.
