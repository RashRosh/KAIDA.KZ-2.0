# D5 — «Рядом» по новому дизайну (B07)

Выбор PO 2026-11-09 после закрытия D4 (`v0.0.89-design-favourites`): следующий экран миграции — «Рядом» (B07). **Статус: приёмка PO состоялась 2026-11-10** (скриншоты шести состояний, 360 px, 2x; PO rework применён и переприёмка пройдена) — merge/tag после branch CI и controller-верdict по обычному gate.

**PO rework 2026-11-10 (применено до приёмки):** кнопка ST05 «Искать по названию» — белый текст без подчёркивания (глобальный `.kaida a:hover` перекрашивал ссылку-кнопку); кнопка ST06 «Повторить» — выровнена по началу текста (34px: иконка 24px + отступ 10px); иконки `refresh` и `aim` взяты из набора QingIcon (`System/refresh.svg`, `Map/crosshair-3.svg`, Apache-2.0, происхождение отмечено в `SearchIcon.tsx`).

## User task и scope

Покупатель открывает «Рядом» из нижней навигации: по явному намерению определяет местоположение и видит ближайшие актуальные предложения сеткой по две карточки в ряд; открывает предложение для подробностей и действий. Authority — два Artifact в [baseline](../../product/DESIGN_BASELINE.md); конкретная доска B07 (2-column grid). Модули: buyer presentation (`NearbyFeed`), additive поле в discovery projection, строки i18n.

Переносится (решения PO 2026-11-03, [FM:Buyer UI](../../product/FEATURE_MAP.md)):

- сетка по две карточки в ряд; в карточке сетки видны фото, название, цена, давность подтверждения и расстояние; продавец, адрес, часы, маршрут и контакты доступны в подробностях (существующей странице предложения);
- плашка давности — по шкале D2 с реальным временем подтверждения (минуты/часы/дни);
- нижняя навигация D2 с активным «Рядом»;
- сохраняется всё закрытое поведение запуска: one-click интент (клик «Рядом» → автоматическая геолокация один раз), deep-link без интента → явная кнопка запуска, reload не повторяет запрос, координаты не сохраняются, ошибки/пусто/загрузка/обновление.

## Explicit out of scope

- Семы discovery API: radius, ordering, eligibility, privacy — без изменений. Единственное изменение данных — additive optional `lastConfirmedAt` в Nearby-проекции (как в D2), из уже существующего `offers.last_confirmed_at`.
- Карта с ценовыми метками и переключатели категорий в текущей реализации отсутствуют и не возвращаются (решения PO 2026-11-03 уже применены к продукту).
- Сердечки в сетке: состав карточки берётся из живой доски B07. Если сердца на доске есть — они вызывают существующий flow избранного; если нет — не добавляются. Не дорисовывать молча.
- Search (остаётся списком), Search Home, Offer, Избранное, «Ещё», Seller/Operator не мигрируются.
- Нет dark theme, offline/cache, гео-диалога сверх закрытого поведения, новых доменных функций.
- Desktop: адаптация сетки до 720px, как в D2; отсутствующий desktop-кадр не объявляется проверенным источником.

## Пересмотр визуальных ограничений и закрытые contracts

- **Явная ревизия presentation-границы**, разрешённая решением PO 2026-11-03 («Карточки в Рядом») и утверждённым источником B07: закрытый [nearby-result-first](../nearby-result-first/SLICE_CONTRACT.md) сохранял «сетку UX1B ResultCard, как в выдаче»; D5 заменяет в Рядом подробные `ResultCard` на карточку сетки B07 без контактов/маршрута/часов/точки/адреса в плитке (как в поиске они остаются).
- Согласованные адаптации закрытого поведения (функция сохраняется, форма — по источнику): кнопка обновления остаётся иконкой в шапке (B07 шапку рисует без неё), счётчик «Найдено рядом: N» остаётся visually-hidden live-статусом; явный запуск по deep-link меняет подпись «Показать товары рядом» → «Определить местоположение» (ST01); в начатом состоянии и при отказе геолокации появляется «Искать по названию» → `/` (ST01/ST04/ST05); retry ошибки загрузки повторяет запрос по уже определённой транзиентной локации без нового вызова геолокации (копия ST06 «Местоположение определено»); E2E s11 обновлены соответственно.
- [UX1C](../UX1C-nearby-geo-intent/SLICE_CONTRACT.md) (one-click geo intent), S9 (transient coordinates, без хранения), S11 (API semantics) — без изменений.
- Источник получен и сохранён: исходные HTML обеих досок (B07 Рядом 1 из 2: ST01, ST02/ST08, ST03/ST07/ST09/ST10; B07 Рядом 2 из 2: ST04/ST08, ST05/ST08, ST06/ST08) и tokens.json дизайн-системы лежат в `docs/slices/design-nearby/verification-evidence-source/` (2026-11-09, из экспорта PO; версия iframe `1793830896-9a07` совпадает с зафиксированной в baseline).
- Состав плитки по исходнику: квадратное фото (aspect 1/1, radius 14), название Roboto 400 15/20 (clamp 2), сердце 44 px в строке названия, цена Geologica 700 20/24 + единица 13/18, плашка давности шкалы D2 (f1–f5) с реальным временем подтверждения, расстояние 13/18 ink2. Продавец, адрес, часы, маршрут и контакты — только на странице предложения. Заголовок «Рядом с вами» Geologica 400 26/32.

## Acceptance criteria

1. Шапка/заголовок «Рядом» и нижняя навигация D2 с активным «Рядом»; счётчик предложений и обновление работают (точная форма — по B07).
2. Успешная выдача — сетка по две карточки в ряд по B07: фото, название, цена, плашка давности (реальное время подтверждения, шкала D2), расстояние; продавец, адрес, часы, маршрут и контакты в карточке сетки не показываются — они на странице предложения.
3. Карточка целиком открывает предложение; возврат — в «Рядом».
4. Поведение запуска без изменений: клик «Рядом» в навигации → ровно один geolocation-вызов → один запрос выдачи; прямой deep-link — без авто-запроса, с явной кнопкой; reload не повторяет; координаты не сохраняются в storage/URL.
5. Состояния: locating/loading — skeleton той же формы, что сетка; geo_error и request_error — компактно с доступным retry; empty — честное состояние без выдуманных данных.
6. `lastConfirmedAt` в Nearby-ответе — additive optional; ranking, eligibility и privacy не зависят от новой визуальной шкалы.
7. Нет горизонтального overflow на 320/360/390/768/1440; при 200% текста данные масштабируются, действия остаются ≥ 44 px; reduced motion уважается.
8. До показа PO агент сравнивает реализацию с живым состоянием B07 на одинаковой CSS ширине/данных, проверяет computed sizes и сохраняет screenshots/report (360 px, 2x). Зелёный CI не заменяет визуальную проверку.

## Verification и manual acceptance

Targeted: существующий E2E Рядом (s11-nearby-discovery: интент, privacy, счётчики вызовов), новый design-nearby spec со скриншотами состояний на 360 px, integration additive-поля. Затем полный unit/integration/E2E, lint/types/build, branch CI, diff audit.

PO принимает цельный сценарий: «Рядом» из навигации → разрешить геолокацию → сравнить сетку с B07 → открыть предложение → Back → обновить → отказ геолокации (retry) → пустая выдача. Проверка агента не является manual acceptance PO. До приёмки и поручения PO нет merge/tag; следующий slice не начинается.

## STOP: `lastConfirmedAt` в Nearby-ответе — ревизия закрытого контракта (§4) — РЕШЕНО PO 2026-11-10

Закрытый интеграционный тест `tests/integration/s11-nearby-discovery.test.ts` прямо запрещал `"lastConfirmedAt"` в сериализованном Nearby-ответе (список forbidden-полей), и E2E `assertDiscoveryPrivacy` повторял то же. Плашка давности B07 (минуты/часы/дни, шкала D2) без точного времени подтверждения невозможна; из публичного `actuality.days` получаются только дни, что расходится и с B07, и с направлением PO от 2026-11-03 (B-CONFIRM-TIME).

**Предлагаемая ревизия (соответствует решению PO по D2):** распространить на Nearby-проекцию ту же additive public metadata — optional `lastConfirmedAt` ISO из уже существующей и уже публичной колонки `offers.last_confirmed_at` (публична в BuyerOffer и в Search-выдаче с `v0.0.87`). Ranking, eligibility, radius и privacy не меняются; запрещёнными остаются сырые координаты. Обновляются только ассерты о метаданных в интеграционном тесте s11 и в `assertDiscoveryPrivacy` E2E.

Альтернатива (если PO не принимает): плашка по целым дням из `actuality.days` без минут/часов — экран заметно расходится с B07, и вопрос выносится на приёмку как известное отступление.

**Решение PO (2026-11-10): вариант 1, принято.** Применено: optional `lastConfirmedAt` ISO в Nearby-проекции из существующей колонки `offers.last_confirmed_at`; ranking/eligibility/радиус и запрет сырых координат без изменений; обновлены ассерты о метаданных в интеграционном тесте s11 и `assertDiscoveryPrivacy` E2E.
