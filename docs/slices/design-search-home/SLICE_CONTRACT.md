# D6 — Главная поиска по новому дизайну (B02)

Выбор PO 2026-11-11 после закрытия D5 (`v0.0.90-design-nearby`): следующий экран миграции — главная поиска, Search Home (B02). Решение PO 2026-11-11: **поведение главной сохраняется, меняется только вид.** **Статус: APPROVED PO 2026-11-11 — реализация разрешена.** PO согласился не переносить строку «Искать как введено» и категорию подсказки (см. Explicit out of scope).

## User task и scope

Покупатель открывает вкладку «Поиск», ещё ничего не искав в этой вкладке браузера: видит заголовок, поле поиска и популярные запросы; вводит название (с подсказками каталога) или нажимает чип и попадает в выдачу D2. Authority — два Artifact в [baseline](../../product/DESIGN_BASELINE.md); доска «B01–B02 · Старт и главная поиска» (`Main.dc.html`): средний кадр B02.ST01/ST04, правый кадр B02.ST02–ST03. Состояние ошибки поля (B02.ST05) — компонент поля с ошибкой на листе «Палитра, роли и компоненты» (Z1). Модули: buyer presentation (`SearchScreen`, ветка Search Home, `product-suggestions`), строки i18n.

Переносится (B02):

- верхняя полоса с логотипом KAIDA, как на доске;
- заголовок «Что ищете?» (Geologica, стиль `h1` дизайн-системы), под ним поле поиска в верхней части экрана (сейчас поле стоит по центру экрана);
- поле поиска в стиле `search` дизайн-системы: иконка лупы слева, плейсхолдер «Название товара»; стрелка «Искать» появляется только когда в поле есть текст (решение PO 2026-11-05 «сохранить стрелку при вводе», B-LIVE-HOME «только → в поле»); «Очистить» при наличии текста сохраняется;
- видимая подпись «Популярные запросы» над чипами, чипы в стиле `chip` дизайн-системы;
- подсказки каталога при вводе — строки в стиле `rows` с иконкой лупы и выделенной жирным введённой частью названия (B02.ST02), под подписью «Товары каталога»;
- нижняя навигация D2 с активным «Поиском»;
- ошибка пустого запроса — существующий текст «Введите название товара.» в оформлении поля с ошибкой (Z1).

## Сохраняемое поведение (решение PO 2026-11-11)

Всё, что главная делает сейчас, остаётся как есть ([search-home-last-state](../search-home-last-state/SLICE_CONTRACT.md) 6C, [s15b3-buyer-autocomplete](../s15b3-buyer-autocomplete/SLICE_CONTRACT.md), D0, 6B):

- **«Продолжить» (B02.ST04) не переносится.** Если в вкладке уже был поиск, «Поиск» и обычный `/` сразу открывают последнюю выдачу, заново полученную с сервера (6C §3.3). Главная показывается только когда последнего поиска нет; карточки «Вы искали…» на ней нет.
- **Чипов пять, а не семь.** Тот же курируемый набор: Баранина, Говядина, Мёд, Картофель, Кумыс (6C §3.1). Никакой аналитики популярности; динамические чипы — отдельная задача B-CHIPS.
- Подсказки каталога: тот же источник `GET /api/catalog/suggestions`, тот же лимит и порядок (S15B-1), выбор подсказки ищет по выбранному Product, клавиатура и роли listbox сохраняются.
- Осознанный поиск — как сейчас: submit, чип или подсказка; D0-событие пишется только по ним. При открытии главной запрос к `/api/search` не выполняется.
- 6B: общий `/` без маркера по-прежнему уходит на `/welcome`; First Entry не меняется.
- Хранение последнего поиска (`sessionStorage`, без результатов и координат) и нормализация geo-предпочтений не меняются.

## Explicit out of scope

- Выдача (D2), «Рядом» (D5), Предложение (D3), Избранное (D4), First Entry `/welcome` (B01, отложен PO), «Ещё», Жалоба, Вход, кабинет продавца и оператор не мигрируются.
- **Строка «Искать как введено» и подпись «Свободный запрос не создаёт новый товар в каталоге» (B02.ST03) не переносятся.** В продукте «как введено» уже означает поиск без исправления опечатки (`typed=1`, search-typo-suggestions); такая строка в подсказках изменила бы поведение обычного submit. Обычный submit работает как сейчас.
- **Категория справа от подсказки («Овощи», «Бакалея») не показывается:** API подсказок возвращает только id и название; добавлять поле ради этого — изменение API, которого PO не просил.
- Нет новых API, миграций, хранения, dark theme, промо-баннера (B-PROMO), выдачи на главной (B-LIVE-HOME), выбора языка на главной (он остаётся в «Ещё»).
- Desktop: адаптация до 720 px, как в D2; отсутствующий desktop-кадр не объявляется проверенным источником.

## Пересмотр визуальных ограничений и закрытые contracts

- **Явная ревизия presentation-границы 6C §3.1:** «поле поиска по центру основной области» → заголовок и поле в верхней части экрана по B02. Остальные пункты §3.1 (не более 5 чипов, без ленты, без подписи о свежести, без First Entry, без запроса при открытии) сохраняются.
- Видимый заголовок «Что ищете?» заменяет сейчас скрытую подпись поля «Какой товар ищете?»; у поля остаётся доступное имя (label, связанный с полем). Существующие E2E, которые ищут поле по имени, обновляются под новое имя только если оно меняется; поведение, которое они проверяют, не меняется.
- Подсказки на главной переходят из выпадающей карточки поверх экрана в список строк под полем (B02.ST02). В выдаче D2 (компактное поле в шапке) подсказки остаются как сейчас.
- Тексты на казахском для новых строк («Что ищете?», «Название товара», «Товары каталога») — предварительные, как и в прежних slices; окончательный перевод — отдельно.
- Источник: доска прочитана 2026-11-11 из Artifact экранов, версия `1794254812-c359` (в baseline записана `1793830896-9a07`). С тех пор PO разбил холст на страницы: Покупатель, Вход, Продавец (три страницы), Оператор, Система; досок по-прежнему 87, имена файлов и заголовки досок сохранились. B02 — страница «Покупатель», доска «B01–B02 · Старт и главная поиска». Копия `Main.dc.html` сохраняется как локальный evidence slice по прецеденту D5, в Git не включается.

## Acceptance criteria

1. В новой вкладке (последнего поиска нет, маркер есть) `/` показывает главную по B02: логотип, «Что ищете?», поле, подпись «Популярные запросы» и пять чипов, нижнюю навигацию с активным «Поиском». Запроса к `/api/search` нет.
2. Стрелка «Искать» видна только при непустом поле; нажатие стрелки, Enter, чип и выбор подсказки запускают тот же поиск, что сейчас, и открывают выдачу D2.
3. Пустой submit показывает «Введите название товара.» в оформлении поля с ошибкой и не начинает поиск.
4. Подсказки при вводе от двух символов: строки по B02.ST02 с выделенной введённой частью, не больше пяти, клавиатура (↑ ↓ Enter Esc) работает как сейчас.
5. После поиска «Поиск» в навигации и обычный `/` открывают последнюю выдачу, а не главную; карточки «Продолжить» нет нигде.
6. Нет горизонтального overflow на 320/360/390/768/1440; при 200 % текста действия остаются ≥ 44 px; reduced motion уважается.
7. До показа PO агент сравнивает главную с живым B02 на одинаковой CSS-ширине, проверяет computed sizes и сохраняет скриншоты (360 px, 2x): главная, ввод с подсказками, ошибка пустого запроса. Зелёный CI не заменяет визуальную проверку.

## Verification и manual acceptance

Targeted: `search-home-last-state` (главная против восстановления), `search-by-product` (подсказки), D0-события, новый `design-search-home` spec со скриншотами трёх состояний на 360 px 2x. Затем полный unit/integration/E2E, lint/types/build, branch CI, diff audit.

PO принимает сценарий: новая вкладка → главная (сравнить с B02) → ввести «мё» → подсказки → выбрать → выдача → «Поиск» в навигации возвращает выдачу, не главную → новая вкладка → пустой submit → ошибка → чип → выдача. Проверка агента не является manual acceptance PO. До приёмки и поручения PO нет merge/tag; следующий slice не начинается.
