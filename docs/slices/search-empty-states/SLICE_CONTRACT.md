# Slice Contract — Search empty states (блок UX/search, пункт 4)

**Статус: APPROVED rev 2 (PO, 2026-10-08).** Rev 2 = rev 1 + поправка текста: «активных предложений сейчас нет» вместо «активных карточек» (RU) и «белсенді ұсыныстар жоқ» (KK) — слово «Offer» везде «предложение»/«ұсыныс». Решения раздела 10 приняты как рекомендованные (A: без иллюстраций; B: запрос в заголовке; C: «Посмотреть рядом» остаётся; D: полная формулировка; E: «Изменить запрос» основная; F: реализация, затем KK-вычитка). Новые KK-строки не вычитаны носителем и помечены на вычитку. Реализации нет. Порядок блока — `EXECUTION_PLAN.md`. Рекомендуемый reasoning effort реализации: **medium** (публичный UI покупателя и тексты; без данных, миграций, изменения API и ранжирования). Визуалы — `visuals/index.html` (статический прототип на настоящих стилях и шрифтах приложения; открыть: `node docs/slices/search-empty-states/visuals/serve.mjs 3300` из корня репозитория, затем `/docs/slices/search-empty-states/visuals/index.html`).

## 1. Пользовательская задача
Когда поиск не вернул Offers, покупатель понимает, что произошло, и что можно сделать дальше.

## 2. Что есть сейчас (факты из кода и контрактов)
- При `0` Offers результат — одна серая строка `role=status`: «По вашему запросу ничего не найдено.» (`search.empty`) либо, если запрос — известный Product (`resolvedProduct !== null`, S15B-2), «Сейчас предложений нет.» (`search.emptyKnown`). Под строкой пусто; панель сортировки при `0` скрыта; ряд популярных запросов над результатами и нижняя навигация («Поиск / Рядом / Ещё») остаются.
- Различение known-zero / unresolved-zero уже есть в ответе Search (`resolvedProduct`) и в UI; запрос в тексте не повторяется; следующего действия нет (кроме поля, популярных запросов и вкладки «Рядом»).
- «Сообщить, когда появится» намеренно отсутствует (S15B-2 §3.5); подписок, избранного и исправления опечаток нет.
- Существующие возможности для следующего шага: поле запроса, ряд популярных запросов (уже над результатами), вкладка «Рядом» (`/nearby`, геолокация только по явному действию), экран «Ещё».
- Сводный UX/UI-бэклог в репозитории отсутствует (`UX_BACKLOG.md` — пустой inbox); контекст — `BUYER_JOURNEY.md` («пустой, но понятный результат, а не ошибка»), `SEARCH_SYSTEM_SPEC_v0.1.md` §17.2/§17.4 и `PROJECT_RULES.md` §18.4 (системные состояния, честность).

## 3. Предлагаемое поведение (нормативно)
### 3.1 Когда показывается
Блок состояния заменяет серую строку, когда запрос завершился успешно с `0` Offers. Загрузка (skeleton), ошибка, валидация и уведомление о расстоянии — как сейчас; блок не мелькает во время загрузки. Ответ, `resolvedProduct`, набор и порядок Offers не меняются.

### 3.2 Два состояния (тексты RU / KK; запрос — слова покупателя из выполненного поиска, переносятся где угодно)
| | Неизвестный запрос (`resolvedProduct = null`) | Известный товар (`resolvedProduct ≠ null`) |
|---|---|---|
| Заголовок RU | Ничего не найдено по запросу «{запрос}» | По запросу «{запрос}» сейчас нет предложений |
| Пояснение RU | Проверьте написание или попробуйте другое слово, например название товара целиком. | Этот товар есть в каталоге KAIDA, но активных предложений сейчас нет. Загляните позже или посмотрите, что есть рядом. |
| Заголовок KK | «{запрос}» сұрауы бойынша ештеңе табылмады | «{запрос}» сұрауы бойынша қазір ұсыныстар жоқ |
| Пояснение KK | Жазылуын тексеріңіз немесе басқа сөзді қолданып көріңіз, мысалы, тауардың толық атауын. | Бұл тауар KAIDA каталогында бар, бірақ қазір белсенді ұсыныстар жоқ. Кейінірек қараңыз немесе жақын жердегіні көріңіз. |
- Известный товар явно **не** обещает уведомления и не говорит «скоро появится»: только факт и «загляните позже».
- Пояснение неизвестного запроса — общий совет, не исправление: «Возможно, вы ищете…» и автоподмена остаются следующему slice (typo suggestions).

### 3.3 Действия (существующие возможности)
1. **«Изменить запрос» / «Сұрауды өзгерту»** (основная): возвращает фокус в поле запроса и выделяет текст — без нового запроса, без overlay, без события D0; дальше работают подсказки поля как сейчас.
2. **«Посмотреть рядом» / «Жақын жердегіні көру»** (вторая): переход на вкладку «Рядом» тем же способом, что нижняя навигация (геолокация — только по явному действию внутри «Рядом», как сейчас).
- Ряд популярных запросов над блоком остаётся как есть (третье действие, не дублируется).
- Кнопки не меньше `44×44 px`, растут по высоте при длинном тексте/крупном шрифте; порядок фокуса: поле → ряд популярных → «Изменить запрос» → «Посмотреть рядом» → навигация.

### 3.4 Иллюстрации (решение PO)
Лупа (неизвестный запрос) и пустая полка (известный товар) показаны в визуалах как **предложения, не утверждённые ассеты**. По выбору PO: **без иллюстраций** (рекомендуется: нет утверждённых ассетов и правила «новые иконки не рисуются» в `AGENTS.md`; состояния различает заголовок; при ×2 текст и кнопки остаются выше нижней навигации) либо **с иллюстрациями** (простая линейная графика цвета текста, декоративная: `aria-hidden`, без сети, без анимации). Реализация — только выбранный вариант.

### 3.5 Что не меняется
Допуск и релевантность Search, словоформы, сортировки, API и форма ответа, события D0, resolver, подсказки поля, ряд популярных запросов, Nearby (его собственное пустое состояние), карточки и страница Offer, экраны продавца и оператора.

## 4. Вне scope
Уведомления, «Сообщить, когда появится», избранное, подписки на спрос, интересы (S13) на экране пустого результата, исправление опечаток и «Возможно, вы ищете» (следующий slice), расширение радиуса или смена выдачи, новые API/поля, изменение ранжирования, D0 и допуска, пустое состояние Nearby, новая иллюстративная система, изменение ряда популярных запросов.

## 5. Закрытые contracts
**Ревизия (явно):** `S15B-2 known-zero` — изменяются **только** тексты и композиция двух нулевых состояний в UI (серая строка → блок); семантика `resolvedProduct`, форма ответа и правило «известный товар без предложений отличается от неизвестного запроса» сохраняются; пункт «кнопки "Сообщить, когда появится" нет» остаётся в силе; `buyer-screens-mockup` — композиция состояния «пустой результат» экрана результатов (B01).
**Только чтение / не меняются:** S0/S6 (форма ответа Search), S7, S9 / Search sort Rev 3, `search-word-forms`, `search-home-last-state`, S13, S15B-3 (подсказки поля), S15C/D0.

## 6. Risk flags
**Фактические:** публичный UI результатов; **новые RU/KK-строки** (KK — на вычитку, открытое дело); запрос покупателя выводится в заголовке — длинный запрос и слово без пробелов должны переноситься, текст экранируется (React); известный товар «есть в каталоге» — честная формулировка, но не обещание появления; **«Изменить запрос»** меняет фокус/выделение — на телефоне открывает клавиатуру и подсказки поля (ожидаемо); «Посмотреть рядом» уводит с результатов — состояние последнего поиска сохраняется как у вкладки «Рядом»; при ×2 текста блок высокий — прокрутка внутри `main`; существующие тесты, ожидающие `search.empty`/`search.emptyKnown` как единственную строку. **Не затрагиваются:** БД, миграции, API, Search и ранжирование, D0, auth, внешние сервисы, AI.

## 7. Acceptance criteria
1. **Неизвестный запрос + 0 Offers:** заголовок с запросом, пояснение и два действия (RU и KK); текст не содержит слов об уведомлениях и опечатках.
2. **Известный товар + 0 Offers:** отдельный заголовок и пояснение (RU/KK), отличающиеся от неизвестного запроса; `resolvedProduct` и ответ API без изменений.
3. **Есть Offers:** выдача, счётчик, панель сортировки и ряд популярных запросов как раньше; блок не показывается.
4. **«Изменить запрос»:** фокус в поле, текст выделен; новый запрос и событие D0 не отправляются (E2E: ни одного запроса `/api/search` после нажатия).
5. **«Посмотреть рядом»:** открывает `/nearby` как вкладка навигации; геолокация не запрашивается без явного действия внутри «Рядом».
6. **Нет лишнего:** нет кнопок «Сообщить», избранного, подписки, «Возможно, вы ищете»; нет новых запросов, полей API, изменения порядка и допуска (существующие тесты Search/S9/Rev 3/word-forms/D0 без правки утверждений).
7. **Состояния:** загрузка — skeleton без мигания блока; ошибка, валидация, уведомление о расстоянии — как раньше; статус объявляется один раз (`role=status`, `aria-live`).
8. **Доступность:** кнопки ≥ 44×44 px и растут при длинном тексте; видимый фокус; иллюстрация (если выбрана) `aria-hidden`; состояние не только цветом.
9. **Перенос и ширина:** длинный запрос, слово без пробелов, KK, 320 px и текст ×2 — без обрезки и горизонтального скролла (E2E mobile; реальный телефон — у PO).
10. **Строки RU/KK:** новые ключи есть в обоих языках, равенство наборов ключей; KK помечены на вычитку.
11. **Регрессия:** Nearby, карточки, страница Offer, экраны продавца и оператора не изменились; `pnpm verify` зелёный.

## 8. Verification (агентская)
Unit — выбор состояния по `resolvedProduct` и тексты RU/KK, ключи i18n; E2E (mobile, ru + kk) — неизвестный запрос, известный товар (Production KB, без Offers), запрос с Offers, действия, отсутствие запросов после «Изменить запрос», 320 px и ×2; полный `pnpm verify`. Агент подготовит тестовые данные (известный товар без Offers — из Production KB, без изменения данных), ничего в dev-базе не создаётся сверх нужного и записывается для очистки. **Не проверено** (будет в отчёте): реальные телефоны, KK-вычитка.

## 9. Manual acceptance (PO, телефон)
1. Найти запрос-бессмыслицу («лакедра»): понятно, что ничего не найдено, и что делать; нажать «Изменить запрос» — курсор в поле, текст выделен, сразу можно печатать.
2. Найти известный товар без предложений (например «мёд горный», пока нет карточек): текст отличается от первого, нет обещания уведомить; нажать «Посмотреть рядом» — открылась вкладка «Рядом».
3. Найти товар с карточками («Баранина»): выдача как раньше, блока нет.
4. Повторить пп. 1–2 на казахском; затем крупный системный шрифт (и узкий телефон, если есть): ничего не обрезано, кнопки доступны.
PO принимает: исход и следующий шаг понятны, два состояния различаются, лишних функций нет, RU/KK читаются. Технические проверки — агентские.

## 10. Решения PO (приняты как рекомендованные; ниже — варианты)
- **A. Иллюстрации:** без иллюстраций (рекомендуется) / лупа + пустая полка / только одна нейтральная. Решение влияет на высоту блока, но не на логику.
- **B. Запрос в заголовке:** повторять слова покупателя (рекомендуется: видно, что именно искали) либо общий заголовок без запроса.
- **C. Вторая кнопка «Посмотреть рядом»:** оставить (рекомендуется) / убрать (останутся поле и популярные запросы).
- **D. Формулировка известного товара:** «Этот товар есть в каталоге KAIDA, но активных предложений сейчас нет…» (рекомендуется: факт без обещания) либо короче: только «Сейчас предложений нет» плюс кнопки.
- **E. Важность кнопок:** «Изменить запрос» основная, «Посмотреть рядом» вторая (рекомендуется) либо наоборот для известного товара.
- **F. KK-тексты:** вычитка до реализации или после (рекомендуется: реализовать, вычитку записать отдельным пунктом).
Утвердить также визуалы: два состояния, KK, 320 px, длинный запрос, крупный шрифт.

## 11. STOP conditions
Нужно менять API, `resolvedProduct`, допуск/релевантность/сортировку, события D0, добавлять уведомление, избранное, подписку или исправление опечаток; нужен новый ассет без решения PO; «Изменить запрос» отправляет запрос; PO не утвердил визуалы.
