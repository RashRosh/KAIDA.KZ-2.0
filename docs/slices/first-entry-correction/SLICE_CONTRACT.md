# First Entry correction — `/welcome` отдельно от Search `/` (stage 6B)

**Status:** APPROVED — IMPLEMENTATION AUTHORIZED (Controller, 2026-10-04; реализация — после записи этого статуса в `main`).
**Base:** `main` `415a25a` + 6A (`PROJECT_RULES.md` §18.4–18.5, `EXECUTION_PLAN.md` «Текущий repository gate»).
**Branch:** `slice/first-entry-correction-contract` (contract-only).
**Plan:** stage 6B (`EXECUTION_PLAN.md`). Следом: 6C Search Home + состояние поиска, 6D inline-язык, stage 6 Rev 3.
**UX target:** принятый макет (`PROJECT_RULES.md` §18.1), страница FIRST ENTRY: `FEA1` (в том числе переключатель
языка `РУС / ҚАЗ` в шапке), `FEA3` (демо), `fe.css`. Граница доставки — mobile + русский (`PROJECT_RULES.md` §18.5).

## 1. User task

Покупатель, впервые открывший KAIDA, сразу видит First Entry с демо — без экрана выбора языка — и может переключить язык
прямо там. Один раз увидев First Entry, он больше не попадает на него при обычном заходе: сервис открывается на Search,
а `Поиск` в нижней навигации никогда не возвращает на First Entry.

## 2. Маршруты и владение

| Что | Владелец |
|---|---|
| `/welcome` | First Entry / onboarding: свой экран (шапка с языком, заголовок, поле, пример-фикстура, демо, `Разместить товар`). Не режим Search. Показывается всегда, когда открыт напрямую. |
| `/` | Постоянный Search. Никогда не показывает First Entry, демо и пример-карточки. `/?q=…` — выдача как сейчас. |
| Решение «показать ли First Entry» | Только общий вход `/` без `q` и без маркера intro → First Entry. Намерение deep link сохраняется: `/?q=…` и явные ссылки на другие маршруты продукта (`/nearby`, `/offers/…`, `/more`, `/seller…`) onboarding не перехватывает. |
| Маркер «intro показан» | Постоянный (не session-only) first-party маркер браузера/устройства, рабочее имя `kaida_intro_seen`; означает «First Entry был показан». |
| Состояние демо | `kaida_fe_demo_seen` в `localStorage` — как в `first-entry-mobile`; остаётся отдельным от маркера intro. |
| Язык | Прежний locale cookie `kaida_locale`; определение: cookie → язык браузера → `ru`. |

## 3. Behavior

### 3.1 Первый заход
`/` без маркера и без `q` → покупатель попадает на First Entry (`/welcome`). Демо стартует сразу, не дожидаясь выбора
языка. Отдельного языкового экрана нет.

### 3.2 Маркер intro
- Маркер записывается, когда First Entry **показан**, а не только при поиске: любой выход оттуда (поиск, `Рядом`, `Ещё`,
  `Поиск`, `Разместить товар`, закрытие вкладки после показа) считается просмотренным intro.
- После этого обычный `/` открывает Search; нижняя навигация `Поиск` ведёт на `/` и First Entry не открывает.
- `/welcome` доступен напрямую в любой момент: показывает First Entry всегда (с маркером или без), без автоматического
  ухода; из UI продукта на него после первого раза ссылок нет.
- `/?q=…` и явные deep links на другие маршруты продукта не перехватываются onboarding и не обязаны ставить маркер;
  первый общий `/` без `q` после этого всё ещё покажет First Entry один раз.
- Маркер без персональных данных, не credential, отдельный от сессии, locale и demo-состояния: не заменяет и не
  сбрасывает `kaida_fe_demo_seen`, сброс одного не меняет другое. Срок хранения и внутренний механизм контракт не
  фиксирует, пока это не нужно для поведения.
- Cookie недоступны: как и locale cookie, это за пределами гарантий; First Entry и поиск по введённому запросу работают,
  обхода не строим.

### 3.3 First Entry (`/welcome`)
Содержание и поведение — как в `first-entry-mobile` (заголовок, поле с `→` только при тексте, пример-фикстура, демо
один раз, остановка по взаимодействию, `Без регистрации`, `Разместить товар`, нижняя навигация, геолокация не
запрашивается при открытии) с одним отличием в шапке: добавляется переключатель языка из макета `FEA1`.
Поиск из First Entry открывает выдачу `/?q=…`; Back возвращает на `/welcome`.

### 3.4 Язык
- Переключатель в шапке First Entry: `Русский | Қазақша`, полные названия доступны экранному диктору, текущий язык
  отмечен (`aria-pressed`), применяется сразу одним нажатием, без Sheet, radio и «Готово».
- Смена языка не перезапускает демо (как в макете FE0), не стирает введённый текст и не меняет маршрут.
- Первый показ идёт на определённом языке (cookie → браузер → `ru`); сам показ сохранённого выбора не требует.
- Никакой отдельный экран выбора языка не перехватывает маршруты покупателя или продавца: первый заход на любой их
  экран рендерит этот экран на определённом языке. Устаревший код, ставший неиспользуемым, можно удалить.
- `Ещё` → `Язык` в этом slice не меняется (остаётся как есть до 6D).

### 3.5 `/` до slice 6C
`/` без `q` (маркер есть) показывает обычный вход в Search: поле поиска и существующие популярные запросы; без демо,
примера и ленты результатов. Итоговая композиция (поле по центру, ≤5 чипов) и восстановление последнего поиска — 6C.

## 5. Scope / out of scope

**Scope:** маршруты `/welcome` и `/`; решение по маркеру intro; запись маркера; переключатель языка на First Entry;
отсутствие отдельного языкового экрана у покупателя и продавца; временный вход в Search на `/`; тестовая настройка (§8).

**Out of scope:** итоговый Search Home и последнее состояние поиска (6C); inline-язык в `Ещё` (6D); popover сортировки;
Query Log и динамические чипы; новые тексты и анимация First Entry; ссылка «показать intro снова»; desktop; приёмка
казахского; серверное хранение чего-либо; обработка ботов и link preview сверх §6.

## 6. Risk flags

DB migration: no · public API: no · auth/security/privacy: no · concurrency/atomicity: no · data loss: no · external
service: no.

Это не формальные risk flags, а предмет верификации (§8): серверное решение без мигания First Entry и без
редирект-цикла; постоянный маркер intro; сохранение Back; центральная тестовая настройка; перекрытие с закрытым
`first-entry-mobile` (§4). Клиенты без cookie (боты, link preview) получают First Entry на общем `/`, допустимо.

## 7. Acceptance criteria

1. Первый `/` (нет маркера, нет `q`) показывает First Entry; демо стартует сразу; языкового экрана нет.
2. Маркер записан после показа First Entry; следующий обычный `/` открывает Search без промежуточного показа First Entry.
3. `Поиск` в нижней навигации с любого экрана покупателя, включая `/welcome`, ведёт на Search и не открывает First Entry.
4. `/welcome` по прямому адресу всегда показывает First Entry и не уводит оттуда сам.
5. `/?q=…` и любой другой маршрут не переадресуют на First Entry и не ставят маркер.
6. Переключатель на First Entry: два варианта, текущий отмечен, применяется сразу, не перезапускает демо, не теряет текст.
7. Отдельный экран выбора языка не перехватывает маршруты покупателя и продавца; первый заход на любой их экран
   рендерится на cookie → браузер → `ru`.
8. First Entry сохраняет поведение `first-entry-mobile` (демо один раз, пример-фикстура, `→` только с текстом, пустой
   запрос не отправляется, `Разместить товар`, геолокация не запрашивается) на 360 и 390 px по-русски.
9. Поиск с First Entry открывает `/?q=…`; Back возвращает на `/welcome`.
10. Маркер intro и `kaida_fe_demo_seen` независимы: сброс одного не влияет на другое.
11. `/` с маркером и без `q` — вход в Search (поле + существующие чипы), без демо, примера и ленты.
12. Регрессия зелёная; в production-коде нет тестовых веток ради этого slice.

## 8. Verification

- **Предмет проверки:** отсутствие мигания First Entry для вернувшегося покупателя, отсутствие редирект-цикла, Back из
  выдачи на `/welcome`, независимость маркеров, сохранность deep links.
- **Unit:** чистое правило «`/` без `q` и без маркера → First Entry, иначе Search»; независимость маркера и demo-state.
- **E2E (mobile RU):** обычные buyer/search-сценарии стартуют с «язык выбран, intro уже показан» через **один**
  детерминированный центральный вспомогательный механизм состояния браузера, а не правкой каждого файла; сценарии First
  Entry стартуют без маркера и отдельно доказывают AC 1–7, 9–11. Устаревшие проверки языкового gate и старта на `/`
  переносятся на `/welcome` или классифицируются как stale. Production-код под тесты не меняется.
- `pnpm verify` и полный branch CI на точном SHA; manual acceptance на телефоне.

## 9. STOP conditions

- Решение без мигания требует хранения маркера на сервере или в БД.
- Нужна правка закрытых auth/seller-entry/ranking/API контрактов сверх §4.
- Центральная тестовая настройка невозможна без test-only веток в production-коде.
- Redirect-цикл или потеря Back-поведения не устраняются в рамках §3.

## 10. Manual acceptance (телефон, русский, новый профиль браузера)

1. Открыть `/` в чистом профиле: сразу First Entry с анимацией, в шапке `Русский | Қазақша`, языкового экрана нет.
2. Нажать `Қазақша`, затем `Русский`: язык меняется сразу, анимация не повторяется.
3. Ввести запрос и найти: открылась выдача; Back — снова First Entry.
4. Нажать `Поиск` в нижней навигации: открылся Search (поле и чипы), не First Entry.
5. Закрыть вкладку, открыть `/` снова: Search, не First Entry.
6. Открыть `/welcome` напрямую: First Entry; из него `Разместить товар` открывает вход продавца как раньше.
7. Открыть `/seller` в новом профиле: экрана выбора языка нет, страница на русском.
