# Search sorting control UX refresh

**Status:** APPROVED — IMPLEMENTATION AUTHORIZED (PO, 2026-10-06; поведение и визуал: превью `preview2.png` при 320 и 360 px утверждено, включая иконку-слайдеры). Приёмка прежней версии контрола — NOT PASS; этот контракт **заменяет** прежний дизайн (см. §6, «Superseded»). Казахские тексты — черновики на вычитку.
**Base:** `main` после `v0.0.59-search-relevance-default`.
**Plan:** UX-slice между S15B и S15C (`EXECUTION_PLAN.md`, «Deferred UX»). Только интерфейс; backend, допуск, ранжирование, API и Nearby не меняются. Оценка поисковой системы отложена и в этот slice не входит.
**Граница доставки:** mobile + русский (`PROJECT_RULES.md` §18.5).

## 1. User task

Покупатель меняет порядок результатов в компактном ряду прямо над выдачей и одним действием возвращает порядок по умолчанию.

## 2. Фактическое поведение на `main` (evidence)

- Иконка-фильтр справа от поля поиска открывает anchored popover с четырьмя пунктами («По соответствию», «Расстояние», «Цена», «Актуальность»); тап по активному (кроме «По соответствию») меняет direction; popover остаётся открытым после выбора. Под чипами — строка «Порядок: …».
- Отказ геолокации при «Расстояние» возвращает в `relevance` с пояснением; сортировка хранится в `kaida:last-search` (`relevance` — без direction) и восстанавливается через «Поиск» и Back. Контрол есть только на экране результатов.

## 3. Behavior

### 3.1 Контрол — один компактный ряд (решение PO, 2026-10-06; заменяет прежние решения)

**Положение:** один ряд **ниже строки чипов, непосредственно над результатами**. Без большой pill-кнопки, рамки, фона и панели вокруг ряда; без поясняющих подписей. Видимые элементы — обычный текст ≈ 14 px и мелкие иконки; видимая высота ряда ≈ 28 px; зоны нажатия **44×44 px** даёт невидимый отступ (видимые элементы не раздуваются). Ряд в одну строку, без наложения и горизонтального переполнения от 320 px.

**По умолчанию (relevance):** `иконка-слайдеры` / «**По умолчанию**» / индикатор списка. Направления и × нет.

**Явная сортировка:** `иконка-слайдеры` / **текущий критерий + ↑ или ↓** / индикатор списка / **×**. × показывается только для явной сортировки.

Слов «Сортировка», «Сортировать», «По соответствию» в видимых подписях нет; пояснительных подписей нет.

**Выпадающий список** (anchored под рядом, не sheet — `PROJECT_RULES.md` §18.4), компактный, по ширине содержимого (≈ 176 px минимум, не шире экрана за вычетом полей), строки по 44 px, стили существующего popover (`--raised`, `--line`, `--shadow-md`, скругление 12 px, активный пункт `--primary-soft`). **Четыре пункта, в порядке:** «**По умолчанию**» (relevance, без direction), «**По цене**», «**По расстоянию**», «**По актуальности**». Активный явный пункт показывает стрелку направления; для «По умолчанию» стрелки нет. Фраза порядка («дешевле первыми» и т. п.) остаётся в accessible name, второй видимой строки нет. Список остаётся открытым после выбора (как в Rev 3; подтверждено PO) и закрывается тапом вне, Escape или триггером; overlay-правила §18.4 (фокус внутрь один раз, возврат на триггер) сохраняются.

**Взаимодействие:**
- Список открывает **отдельный триггер-индикатор**; значение «По умолчанию» в ряду и иконка **неинтерактивны** (решение PO).
- Выбор **другого** явного критерия применяет его естественное направление (цена — дешевле первыми, расстояние — ближе первыми, актуальность — сначала актуальные).
- Тап по **текущему явному значению** снова меняет направление — и в ряду (по тексту критерия/стрелке), и при выборе активного пункта в списке. **↑/↓ — только индикатор, не отдельное действие.**
- **«По умолчанию»** — обычный пункт списка, не отдельная кнопка сброса: выбор его при явной сортировке возвращает relevance без direction; тап по «По умолчанию», когда он уже активен, ничего не делает.
- **×** (только при явной сортировке) тоже возвращает relevance без direction одним действием.
- Возврат к умолчанию (пункт или ×) меняет только сортировку: запрос, выбранный Product, buyer location и прочее состояние сохраняются; запрос повторяется; результат пишется в last-state (`{sort:'relevance'}` без direction). Во время загрузки ряд неактивен (`aria-disabled`).
- **0 Offers** (включая известный Product без предложений, ошибку, загрузку без предыдущих результатов): весь ряд скрыт; выбранная сортировка в состоянии сохраняется и снова видна, когда появятся результаты.
- Строка «Порядок: …» и любые поясняющие подписи удаляются.

**Иконка:** «слайдеры» — утверждена PO в превью (24 px, штрих 1.75, скруглённые концы, как набор макета); PO явно разрешил добавить её в этом slice (`AGENTS.md`: новые рисованные иконки — только по решению PO). Реализуется как встроенный SVG-компонент рядом с контролом; общий набор `public/kaida/icons` не меняется.

**Accessible names (не видимые подписи; утверждены PO — ограничения на видимые подписи на них не распространяются):** триггер списка — «Порядок результатов» (KK «Нәтижелер реті»); × — «Сбросить сортировку» (KK «Сұрыптауды тастау»), как уже решено PO; кнопка текущего значения — «критерий, фраза порядка» (например, «По цене, дешевле первыми»); группа списка — «Порядок результатов».

### 3.2 «По расстоянию» без геолокации
Как сейчас: выбор «По расстоянию» — явное действие, запрашивает геолокацию один раз; разрешено → `distance`; отказ → пояснение «Для сортировки по расстоянию нужен доступ к местоположению.», состояние `relevance` (ряд в состоянии по умолчанию, × нет), `distance` без координат на сервер не отправляется. Геолокация не запрашивается при открытии списка, при возврате к умолчанию или при восстановлении.

### 3.3 Last-state и Back
Формат `kaida:last-search` не меняется. «Поиск» и Back восстанавливают сортировку как сейчас: явная — со своим direction (ряд показывает её и ×), `relevance` — без direction; `distance` без координат при восстановлении → `relevance`.

### 3.4 Тексты buyer-facing (RU; KK — черновики на вычитку, не утверждены)
- Умолчание: «По умолчанию» (KK «Әдепкі бойынша»).
- Пункты: «По цене» / «По расстоянию» / «По актуальности» (KK «Баға бойынша» / «Қашықтық бойынша» / «Өзектілік бойынша»).
- Фразы порядка (accessible name): цена — «дешевле первыми» / «дороже первыми», расстояние — «ближе первыми» / «дальше первыми»; актуальность — «сначала актуальные» / «сначала менее актуальные» вместо «свежее первыми» / «старее первыми» (KK «алдымен өзектілері» / «алдымен өзектілігі төмені»).
- Слово «свежее» в тексте сортировки не используется (только строки сортировки; прочие тексты не затрагиваются).

## 4. Scope / out of scope

**In scope:** ряд сортировки в `SearchScreen` и его компонент (`SortPopover.tsx`) вместо иконки-фильтра; иконка-слайдеры (после решения §11); тексты §3.4; обновление тестов, находящих контрол и критерии по имени.

## 8. Acceptance criteria

1. Иконки-фильтра нет; один компактный ряд ниже чипов и над результатами, без рамки/фона/панели, в одну строку без наложения и горизонтального переполнения на 320 и 360 px; зоны нажатия ≥ 44×44 px без визуального увеличения ряда.
2. По умолчанию: иконка-слайдеры / «По умолчанию» / индикатор; нет направления и ×. Слов «Сортировка», «Сортировать», «По соответствию» и пояснительных подписей нет; слова «свежее» в тексте сортировки нет.
3. Явная сортировка: иконка / критерий + ↑ или ↓ / индикатор / ×.
4. Список из четырёх пунктов: «По умолчанию», «По цене», «По расстоянию», «По актуальности»; открывается только отдельным триггером.
5. Выбор другого явного критерия — его естественное направление; тап по текущему явному значению (в ряду и в списке) меняет направление; ↑/↓ — не отдельное действие; порядок результатов как в Rev 3.
6. «По умолчанию» — пункт списка: при явной сортировке возвращает relevance без direction; при уже активном — ничего не делает. × (только при явной) делает то же.
7. Возврат к умолчанию сохраняет запрос, выбранный Product, buyer location; `sort=relevance` без direction в запросе и в last-state; геолокация не запрашивается.
8. 0 Offers / загрузка без результатов / ошибка: ряд скрыт; при появлении результатов возвращается с прежней сортировкой.
9. «По расстоянию» без разрешения: один запрос по явному выбору; отказ → пояснение и relevance (ряд по умолчанию, × нет); `distance` без координат на сервер не уходит.
10. «Поиск» и Back восстанавливают явную сортировку (с direction и ×) или умолчание; `distance` без координат → relevance.
11. Клавиатура/диктор: триггер, значение, пункты и × доступны, Escape закрывает список, фокус возвращается на триггер, имена по §3.1; состояние не только цветом.
12. Backend, API, Nearby и порядок явных сортировок не изменены (серверные и ranking-тесты зелёные без правки утверждений порядка).

## 10. Manual acceptance (телефон, русский; БД с KB, «Баранина», свободные «Баранина на кости (свободная)» и «Баранина500г»)

1. Найти «Баранина»: ниже чипов, над карточками — ряд «иконка / По умолчанию / ▾», без рамки и фона; порядок по соответствию; слов «Сортировка» и «По соответствию» нет.
2. Нажать ▾: список «По умолчанию» (активен), «По цене», «По расстоянию», «По актуальности»; тап по «По умолчанию» ничего не меняет.
3. Выбрать «По цене»: ряд — «иконка / По цене ↑ / ▾ / ×»; тап по «По цене ↑» — «↓»; тап по активному «По цене» в списке — снова «↑».
4. Выбрать «По актуальности»: естественное направление «сначала актуальные», слова «свежее» нигде нет.
5. Нажать ×: порядок по умолчанию, ряд «По умолчанию», запрос и выбранный Product на месте. То же — выбор «По умолчанию» из списка.
6. «По расстоянию», отказ геолокации: пояснение, ряд по умолчанию, × нет. С разрешением: ближайшие первыми, × есть.
7. «По цене» → открыть карточку → Back: сортировка и × сохранены; затем «Поиск» в навигации — то же.
8. «Тунец» (нет предложений): ряд не показывается.
9. Проверить на узком экране (320 px): ряд в одну строку, без переполнения.
