# Search sorting control UX refresh

**Status:** DRAFT — на approval PO. **Реализация заблокирована до ответа PO по §11 (Design gaps).**
**Base:** `main` после `v0.0.59-search-relevance-default`.
**Plan:** UX-slice между S15B и S15C (`EXECUTION_PLAN.md`, «Deferred UX» — финальное решение PO 2026-10-06). Это изменение только интерфейса; backend, допуск, ранжирование, API и Nearby не меняются.
**Граница доставки:** mobile + русский (`PROJECT_RULES.md` §18.5); казахский текст — на вычитку.

## 1. User task

Покупатель меняет порядок результатов прямо под строкой поиска и одним действием возвращает естественный порядок по умолчанию.

## 2. Фактическое поведение на `main` (evidence)

- Справа от поля поиска — иконка-фильтр (`SortPopover`, anchored popover) с четырьмя пунктами: «По соответствию» (дефолт, без стрелки), «Расстояние», «Цена», «Актуальность»; тап по активному пункту (кроме «По соответствию») меняет direction; popover остаётся открытым после выбора.
- Под полем и чипами — строка «Порядок: …» (`search.orderCaption`) с фразой текущего порядка; для дефолта — «лучшие совпадения первыми», для актуальности — «свежее первыми».
- Отказ геолокации при «Расстояние» возвращает в `relevance` и показывает пояснение; состояние сортировки хранится в `kaida:last-search` (`relevance` — без direction) и восстанавливается через «Поиск» и Back. Контрол есть только на экране результатов.

## 3. Behavior

### 3.1 Контрол
- Иконка-фильтр и пункт «По соответствию» удаляются. Один **current-sort control** под строкой поиска (положение и вид — §11, на утверждение PO).
- Выпадающий список (anchored, не sheet — `PROJECT_RULES.md` §18.4): **«По актуальности»**, **«По цене»**, **«По расстоянию»**. Активный пункт показывает фразу порядка и стрелку; тап по активному пункту или его стрелке меняет direction (как сейчас); новый критерий начинается с естественного направления. Overlay-правила §18.4 (фокус внутрь один раз, возврат на открывший элемент, Escape, цель ≥ 44 px) сохраняются.
- **Состояние по умолчанию (relevance):** критерий не назван, стрелки и «Сбросить сортировку» нет; relevance никогда не называется «Актуальность» и не предлагается как пункт.
- **Явный выбор:** контрол показывает выбранный критерий и порядок, рядом — **«Сбросить сортировку»**.
- **Сброс** возвращает `relevance` без direction одним действием, повторяет запрос с теми же `q`, выбранным Product, buyer location и прочим состоянием (меняется только `sort`); результат сохраняется в last-state (`{sort:'relevance'}` без direction). Во время загрузки контрол и сброс неактивны (`aria-disabled`), как критерии сейчас.
- **0 Offers** (включая известный Product без предложений, ошибку, загрузку без предыдущих результатов): контрол и «Сбросить сортировку» скрыты; выбранная сортировка в состоянии сохраняется и снова видна, когда появятся результаты.
- Строка «Порядок: …» удаляется (её роль выполняет контрол).

### 3.2 «Расстояние» без геолокации
Как сейчас: выбор «По расстоянию» — явное действие, запрашивает геолокацию один раз; разрешено → `distance`; отказ → пояснение «Для сортировки по расстоянию нужен доступ к местоположению.», состояние `relevance` (контрол в состоянии по умолчанию, «Сбросить сортировку» не показывается), `distance` без координат на сервер не отправляется. Геолокация не запрашивается при открытии списка, при сбросе или при восстановлении.

### 3.3 Last-state и Back
Формат `kaida:last-search` не меняется. «Поиск» и Back восстанавливают сортировку как сейчас: явная — со своим direction (контрол показывает её и «Сбросить сортировку»), `relevance` — без direction; `distance` без координат при восстановлении → `relevance`.

### 3.4 Тексты buyer-facing (RU; KK — черновики на вычитку, не утверждены)
- Контрол по умолчанию: «Сортировка» (KK «Сұрыптау»).
- Пункты: «По актуальности» / «По цене» / «По расстоянию» (KK «Өзектілік бойынша» / «Баға бойынша» / «Қашықтық бойынша»).
- Фразы порядка: цена — «дешевле первыми» / «дороже первыми», расстояние — «ближе первыми» / «дальше первыми» (без изменений); актуальность — «сначала актуальные» / «сначала менее актуальные» вместо «свежее первыми» / «старее первыми» (KK «алдымен өзектілері» / «алдымен өзектілігі төмені»).
- Сброс: «Сбросить сортировку» (KK «Сұрыптауды тастау»).
- Слово «свежее» в тексте сортировки не используется. Эта правка — только строки сортировки; прочие тексты (главная, напоминания продавца) не затрагиваются.

## 4. Scope / out of scope

**In scope:** `SortPopover` / текущий контрол и его размещение в `SearchScreen`; кнопка сброса; скрытие при 0 Offers; тексты §3.4 в каталоге строк; обновление тестов, находящих контрол и критерии по имени.

**Out of scope:** backend eligibility, ranking, `sort`/`direction` API, last-state формат, Nearby (S11), порядок и смысл явных сортировок, relevance-логика; фильтры (расстояние/цена от–до из B07); чипы-фильтры; Search Home; geo-логика сверх §3.2; S15C и всё следующее; уборка не связанного кода.

## 5. Expected modules

`src/app/(buyer)/_ui/SortPopover.tsx` (или его замена), `src/app/(buyer)/_ui/SearchScreen.tsx`, `src/i18n/messages.ts`; E2E-тесты, использующие кнопку «Сортировка» и имена критериев (`s9-search-ranking`, `search-sort-rev3`, `search-home-last-state`, `search-relevance`, `buyer-screens`, `ux1b-marketplace-cards`, `ux2a-header-responsive`). Серверные модули не меняются.

## 6. Closed contracts — ревизии

- **Stage 6 Rev 3 (`search-sort-rev3`) §3.1:** состав popover (четыре пункта после 4b) и его положение; иконка-фильтр; подписи критериев и фраз порядка («свежее первыми»). Семантика сортировок, direction и правило «активный пункт меняет direction» сохраняются.
- **S15B-4b §3.6:** выбираемый пункт «По соответствию» удаляется (временное решение 4b); подпись порядка «лучшие совпадения первыми» исчезает. Режим `relevance`, дефолт и API не меняются.
- **`search-sort-distance` / S9 geo intent:** поведение «Расстояние» = явный geo intent сохраняется (§3.2); меняется только место контрола.
- **`search-home-last-state`:** формат и Back не меняются; добавляется только видимость «Сбросить сортировку» после восстановления явной сортировки.
- **Макет:** `AI-B07 · Search filters` (bottom sheet с тремя блоками, `SELLER_AI_FIRST_DESIGN_REVISION_1.md` §2.5) уже вытеснен решениями PO (anchored, без sheet — §18.4; Rev 3); этот slice подтверждает, что B07 не implementation target для сортировки.

Не ревизии: S15B-4a/4b ranking, S11, `PROJECT_RULES.md` §18.4 (используется anchored-паттерн).

## 7. Risk flags

public API: no · DB migration: no · auth/security/privacy: no (геолокация — по-прежнему только по явному выбору «По расстоянию», координаты не сохраняются) · concurrency/atomicity: no · data loss: no · external service: no. **UI/A11y: YES** — меняется overlay-контрол и порядок фокуса (§18.4), нужна проверка клавиатуры и экранного диктора; много E2E-ожиданий по имени.

## 8. Acceptance criteria

1. Иконки-фильтра и пункта «По соответствию» нет; один контрол сортировки расположен по §11 (после утверждения PO).
2. В dropdown ровно «По актуальности», «По цене», «По расстоянию»; relevance нигде не называется «Актуальность»; слова «свежее» в тексте сортировки нет.
3. По умолчанию контрол в нейтральном состоянии без критерия, стрелки и «Сбросить сортировку».
4. Явный выбор: контрол показывает критерий и порядок; «Сбросить сортировку» видна; тап по активному пункту/стрелке меняет direction, новый критерий — естественное направление; порядок результатов как в Rev 3 (без изменений утверждений порядка).
5. Сброс: `relevance` без direction в запросе и в last-state; запрос, выбранный Product, buyer location и остальное состояние сохранены; порядок дефолтный; геолокация не запрашивается.
6. 0 Offers / загрузка без результатов / ошибка: контрол и сброс скрыты; при появлении результатов возвращаются с прежней сортировкой.
7. «По расстоянию» без разрешения: один запрос геолокации по явному выбору; отказ → пояснение и `relevance`; на сервер `distance` без координат не уходит; сброс и восстановление геолокацию не просят.
8. «Поиск» и Back восстанавливают явную сортировку (с direction и видимой кнопкой сброса) или `relevance`; `distance` без координат → `relevance`.
9. Клавиатура/диктор: контрол и пункты доступны с клавиатуры, Escape закрывает, фокус возвращается на контрол; цели ≥ 44 px; имя контрола включает текущий критерий и порядок; состояние не передаётся только цветом.
10. Backend, API, Nearby и порядок явных сортировок не изменены (серверные и ranking-тесты зелёные без правки утверждений).

## 9. Verification

Unit — тексты и сопоставление фраз; E2E mobile RU — состояние по умолчанию, выбор и смена direction, сброс (запрос, Product, location сохранены), скрытие при 0 Offers, «Расстояние» с отказом и с разрешением (mock geolocation), «Поиск» и Back с явной сортировкой, клавиатура/фокус; полный `pnpm verify`, branch CI.

## 10. Manual acceptance (телефон, русский; БД с KB, «Баранина», свободные «Баранина на кости (свободная)» и «Баранина500г»)

1. Найти «Баранина»: под полем нейтральный контрол «Сортировка», иконки-фильтра нет, «Сбросить сортировку» нет; порядок по соответствию.
2. Открыть контрол: три пункта «По актуальности», «По цене», «По расстоянию».
3. Выбрать «По цене»: контрол показывает «По цене · дешевле первыми», появилась «Сбросить сортировку»; тап по активному пункту/стрелке — «дороже первыми».
4. Выбрать «По актуальности»: порядок «сначала актуальные», слова «свежее» нет.
5. Нажать «Сбросить сортировку»: порядок по соответствию, контрол снова нейтральный, запрос и выбранный Product (если искали через подсказку) на месте.
6. Выбрать «По расстоянию», отказать в геолокации: пояснение, нейтральное состояние, сброса нет. Повторить с разрешением: ближайшие первыми, «Сбросить сортировку» видна.
7. Выбрать «По цене», открыть карточку, Back: сортировка сохранена, сброс виден. Затем «Поиск» в навигации — то же.
8. Найти «Тунец» (нет предложений): контрол и сброс не показываются.

## 11. Design gaps — запрос к PO (`PROJECT_RULES.md` §18.1; макет не дорисован)

Проверено: в принятом макете (`docs/product/mockup/seller-ai-first-rev1/`) покупательский поиск представлен кадрами `B01` (выдача, кнопка «Фильтры» справа от строки) и `B07` (bottom sheet с сортировкой/расстоянием/ценой). Кадров для: current-sort control под строкой поиска, anchored dropdown из трёх критериев, нейтрального и выбранного состояний, «Сбросить сортировку» — **нет**. B07 вытеснен решениями PO (anchored, §18.4; Rev 3). Согласно §18.1 экран без кадра остаётся в реализованном виде, а новое положение/вид требует кадра или разрешения PO. До ответа эти части не реализуются.

**Предложение (строится на существующих классах `ib`/`li`/`btn`/`c`, без новых иконок; на утверждение):**

Положение — одна строка сразу под строкой поиска (над чипами), высота 44–48 px, отступы 12 px как у чипов:
```
[ поле поиска ........................ ]
[ Сортировка ▾ ]                          ← по умолчанию
[ По цене · дешевле первыми ↑ ▾ ]  Сбросить сортировку   ← после явного выбора
[ чипы ... ]
```
- Контрол — pill-кнопка (стиль чипа/`li`), слева, `aria-haspopup`; dropdown anchored под ней (как сейчас popover: те же поверхность, тень, пункты `li` ≥ 48 px, активный пункт `primary-soft`).
- «Сбросить сортировку» — текстовая вторичная кнопка (≥ 44 px) справа в той же строке; при ширине < 360 px переносится под контрол, не обрезается.
- Нейтральное состояние: «Сортировка» + шеврон, без критерия и стрелки.

**Решения PO:**
1. Нужен кадр дизайнера или разрешение сделать описанное самому по этому предложению?
2. Положение: над чипами (предложено, буквально «под поиском») или заменить строку «Порядок: …» внутри выдачи под чипами?
3. Дополнительная цель направления прямо на контроле (стрелка на самой pill) — нет, меняем только в dropdown (предложено)?
4. KK-тексты §3.4 — черновики на вычитку.

## 12. STOP conditions

- Нужно менять backend, API, eligibility, ranking, last-state формат или Nearby.
- Нужен overlay сверх anchored dropdown (sheet/dialog) либо изменение общих `Sheet`/overlay (§18.4).
- Получен ответ PO, требующий нового кадра, но кадра нет.
