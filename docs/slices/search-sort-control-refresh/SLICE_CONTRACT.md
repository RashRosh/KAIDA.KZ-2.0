# Search sorting control UX refresh

**Status:** APPROVED — IMPLEMENTATION AUTHORIZED (PO, 2026-10-06; поправка PO к дизайну контрола внесена, §3.1 / §11). Казахские тексты — черновики на вычитку.
**Base:** `main` после `v0.0.59-search-relevance-default`.
**Plan:** UX-slice между S15B и S15C (`EXECUTION_PLAN.md`, «Deferred UX» — финальное решение PO 2026-10-06). Это изменение только интерфейса; backend, допуск, ранжирование, API и Nearby не меняются.
**Граница доставки:** mobile + русский (`PROJECT_RULES.md` §18.5); казахский текст — на вычитку.

## 1. User task

Покупатель меняет порядок результатов прямо под строкой поиска и одним действием возвращает естественный порядок по умолчанию.

## 2. Фактическое поведение на `main` (evidence)

- Справа от поля поиска — иконка-фильтр (`SortPopover`, anchored popover) с четырьмя пунктами: «По соответствию» (дефолт, без стрелки), «Расстояние», «Цена», «Актуальность»; тап по активному пункту (кроме «По соответствию») меняет direction; popover остаётся открытым после выбора.
- Под полем и чипами — строка «Порядок: …» (`search.orderCaption`) с фразой текущего порядка; для дефолта — «лучшие совпадения первыми», для актуальности — «свежее первыми».
- Отказ геолокации при «Расстояние» возвращает в `relevance` и показывает пояснение; состояние сортировки хранится в `kaida:last-search` (`relevance` — без direction) и восстанавливается через «Поиск» и Back. Контрол есть только на экране результатов.

## 3. Behavior

### 3.1 Контрол
- Иконка-фильтр и пункт «По соответствию» удаляются. Один **компактный ряд** сортировки сразу под строкой поиска (над чипами), без поясняющих подписей; ряд остаётся в одну строку без наложения и горизонтального переполнения на поддерживаемых ширинах мобильных экранов (от 320 px).
- **Состояние по умолчанию (relevance):** одна кнопка «Сортировка» + индикатор выпадающего списка. Критерия, стрелки направления и × нет; relevance никогда не называется «Актуальность» и не предлагается как пункт.
- **Явная сортировка:** ряд из трёх элементов: (1) **текущий критерий + стрелка направления** — одна кнопка, тап по критерию или по стрелке меняет direction; (2) **отдельный триггер выпадающего списка** (индикатор ▾, имя «Сортировка»); (3) **×** — сброс. × показывается только после явного выбора сортировки.
- **Выпадающий список** (anchored, не sheet — `PROJECT_RULES.md` §18.4): **«По актуальности»**, **«По цене»**, **«По расстоянию»**. Активный пункт показывает фразу порядка и стрелку; тап по активному пункту или его стрелке меняет direction (как сейчас); новый критерий начинается с естественного направления; поведение direction не меняется. Overlay-правила §18.4 (фокус внутрь один раз, возврат на открывший элемент, Escape) сохраняются.
- **Сброс (×):** accessible name **«Сбросить сортировку»** (видимого текстового «Сбросить сортировку» нет), цель касания ≥ 44×44 px. Возвращает `relevance` без direction одним действием, повторяет запрос с теми же `q`, выбранным Product, buyer location и прочим состоянием (меняется только `sort`); результат сохраняется в last-state (`{sort:'relevance'}` без direction). Во время загрузки ряд неактивен (`aria-disabled`), как критерии сейчас.
- **0 Offers** (включая известный Product без предложений, ошибку, загрузку без предыдущих результатов): весь ряд скрыт; выбранная сортировка в состоянии сохраняется и снова видна, когда появятся результаты.
- Строка «Порядок: …» и любые поясняющие подписи сортировки удаляются (фразу порядка получают экранный диктор — в имени кнопки критерия — и активный пункт списка).

### 3.2 «Расстояние» без геолокации
Как сейчас: выбор «По расстоянию» — явное действие, запрашивает геолокацию один раз; разрешено → `distance`; отказ → пояснение «Для сортировки по расстоянию нужен доступ к местоположению.», состояние `relevance` (ряд в состоянии по умолчанию, × не показывается), `distance` без координат на сервер не отправляется. Геолокация не запрашивается при открытии списка, при сбросе или при восстановлении.

### 3.3 Last-state и Back
Формат `kaida:last-search` не меняется. «Поиск» и Back восстанавливают сортировку как сейчас: явная — со своим direction (ряд показывает её и ×), `relevance` — без direction; `distance` без координат при восстановлении → `relevance`.

### 3.4 Тексты buyer-facing (RU; KK — черновики на вычитку, не утверждены)
- Контрол по умолчанию: «Сортировка» (KK «Сұрыптау»).
- Пункты: «По актуальности» / «По цене» / «По расстоянию» (KK «Өзектілік бойынша» / «Баға бойынша» / «Қашықтық бойынша»).
- Фразы порядка: цена — «дешевле первыми» / «дороже первыми», расстояние — «ближе первыми» / «дальше первыми» (без изменений); актуальность — «сначала актуальные» / «сначала менее актуальные» вместо «свежее первыми» / «старее первыми» (KK «алдымен өзектілері» / «алдымен өзектілігі төмені»).
- Сброс: × с accessible name «Сбросить сортировку» (KK «Сұрыптауды тастау»).
- Слово «свежее» в тексте сортировки не используется. Эта правка — только строки сортировки; прочие тексты (главная, напоминания продавца) не затрагиваются.

## 4. Scope / out of scope

**In scope:** `SortPopover` / текущий контрол и его размещение в `SearchScreen`; кнопка сброса; скрытие при 0 Offers; тексты §3.4 в каталоге строк; обновление тестов, находящих контрол и критерии по имени.

**Out of scope:** backend eligibility, ranking, `sort`/`direction` API, last-state формат, Nearby (S11), порядок и смысл явных сортировок, relevance-логика; фильтры (расстояние/цена от–до из B07); чипы-фильтры; Search Home; geo-логика сверх §3.2; S15C и всё следующее; уборка не связанного кода.

- **S15B-4b §3.6:** выбираемый пункт «По соответствию» удаляется (временное решение 4b); подпись порядка «лучшие совпадения первыми» исчезает. Режим `relevance`, дефолт и API не меняются.
- **`search-sort-distance` / S9 geo intent:** поведение «Расстояние» = явный geo intent сохраняется (§3.2); меняется только место контрола.

- **Макет:** `AI-B07 · Search filters` (bottom sheet с тремя блоками, `SELLER_AI_FIRST_DESIGN_REVISION_1.md` §2.5) уже вытеснен решениями PO (anchored, без sheet — §18.4; Rev 3); этот slice подтверждает, что B07 не implementation target для сортировки.

## 7. Risk flags

public API: no · DB migration: no · auth/security/privacy: no (геолокация — по-прежнему только по явному выбору «По расстоянию», координаты не сохраняются) · concurrency/atomicity: no · data loss: no · external service: no. **UI/A11y: YES** — меняется overlay-контрол и порядок фокуса (§18.4), нужна проверка клавиатуры и экранного диктора; много E2E-ожиданий по имени.

## 8. Acceptance criteria

1. Иконки-фильтра и пункта «По соответствию» нет; один компактный ряд сортировки сразу под строкой поиска, в одну строку без наложения и горизонтального переполнения от 320 px.
2. В dropdown ровно «По актуальности», «По цене», «По расстоянию»; relevance нигде не называется «Актуальность»; слова «свежее» в тексте сортировки нет.
3. По умолчанию — только «Сортировка» + индикатор списка: без критерия, стрелки направления и ×.
4. Явный выбор: ряд показывает критерий + стрелку направления, отдельный триггер списка и ×; тап по критерию или стрелке (и по активному пункту списка) меняет direction, новый критерий — естественное направление; порядок результатов как в Rev 3 (без изменений утверждений порядка).
5. Сброс (× с accessible name «Сбросить сортировку», цель ≥ 44×44 px): `relevance` без direction в запросе и в last-state; запрос, выбранный Product, buyer location и остальное состояние сохранены; порядок дефолтный; геолокация не запрашивается.
6. 0 Offers / загрузка без результатов / ошибка: весь ряд скрыт; при появлении результатов возвращаются с прежней сортировкой.
7. «По расстоянию» без разрешения: один запрос геолокации по явному выбору; отказ → пояснение и `relevance` (ряд в состоянии по умолчанию, × нет); на сервер `distance` без координат не уходит; сброс и восстановление геолокацию не просят.
8. «Поиск» и Back восстанавливают явную сортировку (с direction и видимым ×) или `relevance`; `distance` без координат → `relevance`.
9. Клавиатура/диктор: кнопка критерия, триггер списка, пункты и × доступны с клавиатуры, Escape закрывает список, фокус возвращается на триггер; цели ≥ 44 px; имя кнопки критерия включает критерий и порядок; состояние не передаётся только цветом.
10. Backend, API, Nearby и порядок явных сортировок не изменены (серверные и ranking-тесты зелёные без правки утверждений).

## 9. Verification

Unit — тексты и сопоставление фраз; E2E mobile RU — состояние по умолчанию, выбор и смена direction, сброс (запрос, Product, location сохранены), скрытие при 0 Offers, «Расстояние» с отказом и с разрешением (mock geolocation), «Поиск» и Back с явной сортировкой, клавиатура/фокус; полный `pnpm verify`, branch CI.

## 10. Manual acceptance (телефон, русский; БД с KB, «Баранина», свободные «Баранина на кости (свободная)» и «Баранина500г»)

1. Найти «Баранина»: под полем один компактный ряд «Сортировка ▾», иконки-фильтра, подписей и × нет; порядок по соответствию.
2. Открыть список: «По актуальности», «По цене», «По расстоянию».
3. Выбрать «По цене»: ряд — «По цене ↑» + триггер ▾ + ×; тап по «По цене ↑» (или по стрелке) — «↓» (дороже первыми); ряд в одну строку, без переполнения.
4. Выбрать «По актуальности»: порядок «сначала актуальные», слова «свежее» нигде нет.
5. Нажать ×: порядок по соответствию, ряд снова «Сортировка ▾», запрос и выбранный Product (если искали через подсказку) на месте.
6. Выбрать «По расстоянию», отказать в геолокации: пояснение, ряд по умолчанию, × нет. Повторить с разрешением: ближайшие первыми, × видна.
7. Выбрать «По цене», открыть карточку, Back: сортировка сохранена, × виден. Затем «Поиск» в навигации — то же.
8. Найти «Тунец» (нет предложений): ряд сортировки не показывается.

## 11. Design gaps — решение PO (поправка PO, 2026-10-06)

В принятом макете нет кадров для этого контрола (есть `B01` / `B07`; B07 — bottom sheet — вытеснен решениями PO, §18.4, Rev 3). PO разрешил реализацию по описанию §3.1: один компактный ряд под строкой поиска без поясняющих подписей — по умолчанию «Сортировка» + индикатор списка; при явной сортировке критерий + стрелка направления, отдельный триггер списка и ×. Видимого текстового «Сбросить сортировку» нет — только × с accessible name. Строится на существующих классах (`ib`, `li`, иконки макета `down` / `close`, текстовые стрелки ↑ ↓), без новых нарисованных иконок. Положение — над строкой чипов (предложение контракта принято вместе с поправкой). Направление меняется тапом по критерию/стрелке в ряду и по активному пункту списка.
