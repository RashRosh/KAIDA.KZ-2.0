# S-WHOLESALE (slice 2): «Только опт» — Slice Contract

**Статус: APPROVED — PO, 26.11.2026** (решения по 3 открытым вопросам делегированы PO с критерием максимального комфорта для большинства пользователей; уточнение по сортировке: оптовая цена не участвует в сортировке). Основание: [CJM](../../product/CUSTOMER_JOURNEY_MAP.md#решения-от-24112026), [реестр влияния §1](../../reviews/CJM_DECISIONS_2026-11-24_CONTRACT_IMPACT.md#1-опт--вторая-строка-той-же-карточки) и закрытый [slice 1](../wholesale-price/SLICE_CONTRACT.md) (`v0.0.94-wholesale-price`).

## 1. Пользовательская задача

Продавец, который продаёт товар только партиями (без розницы), публикует карточку с оптовой ценой, свободной единицей и минимальной партией. Покупатель в выдаче, Nearby, Избранном и на странице товара сразу видит, что товар продаётся **только оптом** (оптовая цена никогда не выдаётся за розничную), а при сортировке по цене оптовые предложения не мешают розничным.

## 2. Поведение

### 2.1 Продавец: режим «Только оптом»

- В редакторе карточки в блоке цены — компактный переключатель **«Только оптом»** (inline `role="switch"`, ≥ 44 px, §18.4). По умолчанию выключен.
- Когда переключатель выключен — поведение полностью как в slice 1 (обязательная розничная цена + необязательная оптовая строка с обязательным пересчётом партии).
- Когда «Только оптом» включён:
  - поле розничной цены скрывается и не требуется;
  - «Цена за» (`кг / шт / л / упак. / Другое`, с упаковкой для `упак.`/`шт`) остаётся свободной обязательной единицей оптовой цены (например `кг`, `шт` или «Другое: ящик»);
  - оптовая цена и минимальная партия обязательны; в окне «Оптовая цена» поле «Сколько {unit} {inOne}» **необязательно** (если указано — показывается `(≈ N × M {unit})`, если нет — только `от N {тара}`); кнопка «Убрать оптовую цену» в этом режиме скрыта;
  - индивидуальные розничные цены точек (`ownPrice`) не применяются: опт общий на всю карточку.
- Переход между режимами на существующей карточке:
  - **«Только оптом» → с розницей:** продавец выключает переключатель и вводит розничную цену; если у опта тара ≠ единице и пересчёт был пуст, строка опта помечается `needsReview` до заполнения пересчёта (правило slice 1).
  - **С розницей → «Только оптом»:** продавец включает переключатель (если опт ещё не заполнен, заполняет его) и публикует через ChangeSet; на экране подтверждения видно изменение `было → стало`.
- «Моя витрина», экран карточки, превью до и после публикации, «Актуальность · N» и одиночное подтверждение работают для «только опт» без падений при `price = null`. Подпись подтверждения для «только опт» — «Товар есть, цена та же» (одна цена), для смешанной карточки — «Товар есть, цены те же».

### 2.2 Покупатель: отображение и сортировка

- В выдаче, Nearby, Избранном, на странице товара и в превью продавца у карточки «только опт» (`price = null`) вместо розничной строки рисуется крупная строка оптовой цены с явной текстовой меткой **`ОПТ`** (не только цветом) и строкой минимальной партии под ней:
  `650 ₸ / кг  ОПТ`
  `от 1 ящика (≈ 10 кг)` (или `от 1 ящика`, если пересчёт не указан).
- Вместо отсутствующей розницы никогда не показываются `0 ₸`, прочерк или «по запросу» (§18.4 «Честность»).
- **Сортировка по цене (`sort=price`, `asc` и `desc`, ревизия `search-sort-rev3`):** оптовая цена **не используется в сортировке**. Все предложения с розничной ценой всегда идут **перед** «только опт» (отсортированные по розничной сумме как раньше). Предложения «только опт» идут после розничных и упорядочиваются между собой по свежести (`lastConfirmedAt desc → Offer.id`). Сортировки `actuality`, `distance` и Nearby не меняются.

### 2.3 Данные, API и смежные пути

- Миграция `0033_wholesale_only.sql`:
  - `offers_active_price_required`, `offers_future_price_required`, `seller_change_items_future_price_required`: обязательна розничная цена (`price_amount IS NOT NULL AND price_currency = 'KZT'`) **или** валидная оптовая цена (`wholesale_price_amount IS NOT NULL`).
  - `seller_change_items_price_shape`: допускает `price_amount IS NULL AND price_currency IS NULL` при непустом `price_unit_code`, если задан `wholesale_price_amount`.
  - `offers_wholesale_valid` и `seller_change_items_wholesale_valid`: при `price_amount IS NOT NULL` пересчёт для тары ≠ единице по-прежнему обязателен; при `price_amount IS NULL` («только опт») `wholesale_per_container` может быть `NULL` (или `> 0`, не `NaN`/`Infinity`).
- Публичный buyer DTO (`SearchOffer`): `price` допускает `null` только когда присутствует `wholesale`; у «только опт» `wholesale` несёт также `unit: string | null` (для `priceBasisText`). Карточки с розницей сохраняют прежнюю форму DTO без изменений.
- Оператор (`operator-post-check`) и жалобы (`buyer-offer-reports`): принимают и показывают карточки «только опт» без ошибок при `price_amount IS NULL`.
- Текстовый ввод (`text-price-update`, `text-switch-on`) и пакетный ввод S12: не создают «только опт»; текстовое ценовое обновление пропускает «только опт» (не придумывает розницу); reconfirm / undo / deactivate / activate работают для «только опт» штатно.

## 3. Вне scope

- Своя оптовая цена у отдельной торговой точки.
- Фильтр «опт / розница», сортировка по оптовой цене, сравнение «выгоднее на N %».
- Разбор «только опт» из текстового, пакетного, голосового или фото-ввода.
- Новые статусы ChangeSet и изменение порогов актуальности 2/7/14.

## 7. Acceptance criteria

1. Продавец включает «Только оптом», выбирает единицу, указывает оптовую цену и партию (с пересчётом или без) и публикует карточку через ChangeSet.
2. Попытка сохранить/опубликовать карточку без розничной и без оптовой цены отклоняется и в UI, и на сервере/БД.
3. Покупатель в выдаче, Nearby, Избранном и на странице товара видит крупную оптовую цену с текстовой меткой `ОПТ` и минимальную партию (без `0 ₸` и без подмены розницы).
4. При сортировке по цене (`asc` и `desc`) все предложения с розницей идут выше «только опт»; «только опт» идут после них по свежести (оптовая цена в сортировке не участвует).
5. Продавец может перевести карточку «только опт» в смешанную (добавив розницу; при отсутствии пересчёта редактор требует заполнить его) и обратно — убрать розницу, оставив «только опт».
6. Подтверждение актуальности («Товар есть, цена та же», «Всё актуально · N»), выключение и включение работают для «только опт».
7. Превью продавца, жалобы покупателя и лента оператора работают на карточке «только опт» без ошибок.
8. Существующие розничные и смешанные карточки работают без регрессий; ключи `ru` и `kk` полные.

## 9. Manual acceptance (телефон, русский)

1. Продавец создаёт карточку «Томаты опт», включает «Только оптом», выбирает «кг», вводит `450 ₸`, `1 мешок` (без пересчёта) и публикует.
2. Покупатель ищет «томаты»: видит крупно `450 ₸ / кг ОПТ` и `от 1 мешка`. На странице товара — то же.
3. Покупатель включает сортировку «По цене» (дешевле / дороже): розничные предложения выше «только опт».
4. Продавец открывает карточку на витрине и жмёт «Товар есть, цена та же» — бейдж «Сегодня», опт сохранён.
5. Продавец выключает «Только оптом», вводит розничную цену `600 ₸`: редактор просит заполнить пересчёт для мешка; после ввода `20 кг` карточка публикуется как смешанная.
